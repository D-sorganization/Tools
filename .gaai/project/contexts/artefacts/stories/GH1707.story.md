# GH1707: Assessment: 33% of source files lack type annotations on function signatures

**Source:** D-sorganization/Tools#1707

## Description

## Assessment Category: Pragmatic Programmer — Assertive Programming / Types

**Severity:** Medium — For a shared library, type annotations are documentation.

### Finding

- **757 total .py files** in src/ (non-test)
- **505 files** contain at least one `def ... -> ...:` return annotation
- **252 files** (~33%) have no return-type annotations at all
- **652 files** use `from __future__ import annotations` (good)

### Impact

Downstream consumers (UpstreamDrift, Gasification_Model) benefit from type annotations for IDE autocompletion and static analysis. Missing annotations on public API functions force consumers to read source code to understand return types.

### Recommendation

1. Prioritize adding type annotations to `src/shared/python/` public functions
2. The 9% missing-docstring rate in shared/ is good — maintain that standard
3. Consider enabling `disallow_untyped_defs = true` in mypy.ini for `src/shared/python/` only
