# GH1692: Assessment: 10 god classes with 25+ methods in shared library

**Source:** D-sorganization/Tools#1692

## Description

## Assessment Category: H — High Coupling (God Classes)

**Severity:** Medium — Large classes with many methods violate SRP and resist testing.

### Finding

**Classes with >25 methods (src/shared/ only):**
1. `URDFTextEditor` — 38 methods (`model_generation/editor/text_editor.py`)
2. `UnitConversionService` — 38 methods (`calculators/conversion/service.py`)
3. `CalculatorStateMixin` — 35 methods (`ui/mixins/calculator_state_mixin.py`)
4. `DataProcessorWidget` — 29 methods (`ui/widgets/data_processor_widget.py`)
5. `ModelGenerationAPI` — 27 methods (`model_generation/api/rest_api.py`)
6. `ThemeManager` — 27 methods (`theme/theme_manager.py`)
7. `ProcessingMixin` — 26 methods (`signal_toolkit/widget_processing.py`)
8. `FrankensteinEditor` — 25 methods (`model_generation/editor/frankenstein_editor.py`)
9. `DataProcessor` — 25 methods (`data_processing/processor.py`)
10. `DataProcessorEngine` — 25 methods (`data_processing/core.py`)

### Impact

These are in `src/shared/python/` which is the public API consumed by UpstreamDrift and Gasification_Model. Fat interfaces make versioning and breaking-change management harder.

### Recommendation

Apply Interface Segregation Principle. For example, `UnitConversionService` (38 methods) could be split by unit category (temperature, pressure, flow rate, etc.).

## Acceptance Criteria

1. The issue described in #1692 is resolved
2. All new code has tests (TDD)
3. `ruff check` passes on modified files
4. No new `print()` calls in `src/`
5. PR created targeting `staging` branch with clear description
