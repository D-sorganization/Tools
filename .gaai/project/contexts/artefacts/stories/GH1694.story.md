# GH1694: Assessment: 6 src/ files use xml.etree.ElementTree without defusedxml for parsing

**Source:** D-sorganization/Tools#1694

## Description

## Assessment Category: J — Security (XML External Entity)

**Severity:** Medium — `xml.etree.ElementTree` is vulnerable to XXE attacks when parsing untrusted input.

### Finding

6 production files import `xml.etree.ElementTree` for parsing. While `defusedxml` is a declared dependency and is used in some files, these files use the stdlib version:

1. `src/shared/python/humanoid_character_builder/generators/urdf_generator.py` — imports both ET and defusedxml.minidom
2. `src/shared/python/model_generation/editor/text_editor.py` — imports both ET and DefusedET
3. `src/shared/python/model_generation/converters/urdf_parser.py` — imports both ET and DefusedET
4. `src/shared/python/model_generation/converters/format_utils.py` — imports StdET
5. `src/shared/python/model_generation/converters/mjcf_converter.py` — imports ET only
6. `src/shared/python/model_generation/converters/simscape/mdl_parser.py` — imports ET only

Files 5-6 use `xml.etree.ElementTree` without `defusedxml` at all.

### Recommendation

Replace `xml.etree.ElementTree.parse()` / `fromstring()` with `defusedxml.ElementTree` equivalents. The `nosec` annotation on `urdf_builder_gui` files is acceptable since input is self-generated.
