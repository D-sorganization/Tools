# GH1700: Assessment: Pragmatic Programmer — Broken Windows in contracts module import paths

**Source:** D-sorganization/Tools#1700

## Description

## Assessment Category: Pragmatic Programmer — Broken Windows

**Severity:** Medium — Inconsistent import paths create confusion and fragile module resolution.

### Finding

The `contracts` module is imported via 3 different path styles across the codebase:

**Style 1 — Bare import (33 files):**
```python
from contracts import require  # Depends on sys.path containing src/shared/python
```

**Style 2 — Absolute path from src root (10 files):**
```python
from src.shared.python.contracts import require  # Depends on CWD
```

**Style 3 — Shared path (1 file):**
```python
from shared.python.cors import add_cors_middleware  # Depends on sys.path containing src
```

### Impact

- Tests work because pytest.ini sets `pythonpath` to include `src/shared/python`
- `pip install ud-tools` would NOT resolve `from src.shared.python.contracts` (absolute path)
- If `sys.path` order changes, the wrong `contracts` module could be imported (there are 7 files named `contracts.py` in the repo)

### Recommendation

1. Standardize on package-relative imports: `from contracts import require` (bare)
2. Remove all `from src.shared.python.contracts` patterns — these will break in packaged installs
3. Consider namespacing: rename to `ud_contracts` to avoid collisions with other packages
