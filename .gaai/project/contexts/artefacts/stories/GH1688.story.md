# GH1688: Assessment: 6 test failures on staging — modern_robotics logging + missing optional deps

**Source:** D-sorganization/Tools#1688

## Description

## Assessment Category: D — DRY / Delivery (Broken CI on staging)

**Severity:** High — staging branch has failing tests.

### Finding

Running the full test suite (excluding broken collection modules) produces 6 failures:

1. **tests/test_gh1655_print_to_logging.py::TestModernRoboticsLogging::test_module_has_logger** — `modern_robotics.py` has no `_logger` attribute
2. **tests/test_gh1655_print_to_logging.py::TestModernRoboticsLogging::test_logger_name_is_module** — AttributeError (no logger)
3. **tests/test_gh1655_print_to_logging.py::TestModernRoboticsLogging::test_import_logging_present** — `logging` not imported in modern_robotics.py
4. **tests/heavy_integration/test_tools_contracts.py::TestTrimeshGeometryContracts::test_box_mesh_is_watertight** — No module 'trimesh'
5. **tests/heavy_integration/test_tools_contracts.py::TestTrimeshGeometryContracts::test_mesh_boolean_intersection** — No module 'trimesh'
6. **tests/heavy_integration/test_tools_contracts.py::TestEzdxfPIDContracts::test_pid_drawing_entities_valid** — No module 'ezdxf'

### Root Cause

- GH1655 story was delivered (print-to-logging migration) but `modern_robotics.py` was not migrated. Tests were written asserting the migration, but the migration itself was never applied.
- Heavy integration tests import optional deps (trimesh, ezdxf) without guards.

### Recommendation

1. Add `import logging` and `_logger = logging.getLogger(__name__)` to `modern_robotics.py`, replace 2 print() calls with logger.warning()
2. Add `pytest.importorskip()` guards to heavy_integration tests
