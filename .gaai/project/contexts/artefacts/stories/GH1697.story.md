# GH1697: Assessment: CI only delta-checks — full-repo ruff/mypy/format violations go undetected

**Source:** D-sorganization/Tools#1697

## Description

## Assessment Category: M — Monitoring (CI Coverage Gaps)

**Severity:** High — The delta-only CI approach creates a ratchet problem where existing violations are never caught.

### Finding

The CI workflow (`ci-standard.yml`) only lints/formats/typechecks **changed files**:

```yaml
xargs -r -d '\n' ruff check < changed_python_files.txt
xargs -r -d '\n' ruff format --check < changed_python_files.txt
xargs -r -d '\n' mypy --ignore-missing-imports < filtered_mypy_files.txt
```

**Consequences observed:**
1. 25 files have ruff format violations that have accumulated undetected
2. 1,147 type:ignore comments with no full-repo mypy run to verify they are still needed
3. No T201 rule in ruff.toml means print() calls are invisible even in delta checks

Additionally, several directories are excluded from all checking:
- `src/data_processing` (excluded from ruff.toml)
- `src/document_processing` (excluded from ruff.toml)
- `src/pendulum_simulator` (excluded from ruff.toml)
- `src/shared/python/` (excluded from mypy in CI)

### Recommendation

1. Add a weekly/nightly full-repo lint+format+type check job (can be non-blocking initially)
2. Track violation counts as metrics to prevent regression
3. Gradually remove ruff.toml exclusions as modules are cleaned up

## Acceptance Criteria

1. The issue described in #1697 is resolved
2. All new code has tests (TDD)
3. `ruff check` passes on modified files
4. No new `print()` calls in `src/`
5. PR created targeting `staging` branch with clear description
