# E01S01: Configure, optimize, and compare force-source swing strategies

As a user exploring double-pendulum golf mechanics,
I want to select a starting pose and optimization settings and then compare the
resulting objective-specific swings,
so that I can see the motion, speed, loading, and robustness differences together.

## Acceptance Criteria

1. Given the double-pendulum model, when the user changes arm swing or wrist cock,
   then the optimizer receives that visible starting pose without requiring code edits.
2. Given an objective selection, wrist torque limit up to 30 N m, and quick or thorough
   search, when the user clicks Optimize, then progress and a result or actionable error
   are shown while preventing duplicate concurrent runs.
3. Given a valid registered comparison artifact, when it is loaded, then all five
   objective scenarios are available with their provenance and robustness summaries;
   invalid or unsupported artifacts are rejected clearly.
4. Given two or more scenarios, when comparison playback runs, then animations share
   one time control and can be paused, scrubbed, restarted, and inspected together.
5. Given selected scenarios, when supplemental plots are visible, then clubhead speed,
   shoulder torque, and wrist torque use aligned time axes, units, legends, and readable
   zero references.
6. The interface discloses that force-source terms are coordinate/model dependent and
   that the results are exploratory rather than individualized swing advice.
7. Given a candidate trajectory, when the browser optimizer qualifies impact, then it
   requires a non-looping first pass near the bottom of the arc with predominantly
   horizontal, rightward clubhead velocity.
8. Unit, integration, browser-journey, type, and production-build checks pass at both
   desktop and narrow responsive widths.
