# GH1687: Assessment: 27 test collection errors — folder_tool and programmatic_pid suites broken

**Source:** D-sorganization/Tools#1687

## Description

## Assessment Category: C — Correctness (Test Suite Health)

**Severity:** High — 27 test files fail to collect, masking potential regressions.

### Finding

`pytest tests/ --co` reports 27 collection errors:
- **11 in tests/folder_tool/**: `ModuleNotFoundError: No module named 'Folders_Tool_r0'`
- **16 in tests/programmatic_pid/**: `ModuleNotFoundError: No module named 'ezdxf'`

These tests import modules at collection time without guarding for optional dependencies, causing hard failures that block `pytest -x`.

### Impact

Running `pytest tests/ -x` immediately fails on the first folder_tool test. The only way to run the test suite is `--ignore=tests/folder_tool --ignore=tests/programmatic_pid`.

### Evidence

```
$ python3 -m pytest tests/ --co -q 2>&1 | tail -3
4096 tests collected, 27 errors in 6.47s
```

### Recommendation

1. Add `pytest.importorskip("Folders_Tool_r0")` / `pytest.importorskip("ezdxf")` guards
2. Or add `folder_tool` and `programmatic_pid` to `norecursedirs` in `pytest.ini`
3. These directories should have been caught by the existing `norecursedirs` exclusion for `folder_packer_pro` — folder_tool is a different module

### Related

- The `norecursedirs` in pytest.ini already excludes `folder_packer_pro` but not `folder_tool`
