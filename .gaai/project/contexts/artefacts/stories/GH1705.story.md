# GH1705: Assessment: Pragmatic Programmer — Decoupling (calculate_pressure_drop has 4 definitions)

**Source:** D-sorganization/Tools#1705

## Description

## Assessment Category: Pragmatic Programmer — Decoupling / DRY

**Severity:** Medium — Key engineering functions are duplicated across multiple modules.

### Finding

**Duplicated function names with >50 line bodies (3+ definitions):**
- `calculate_pressure_drop` — **4 definitions** across:
  - `scrubber_calculator.py` (55 lines)
  - `pressure_drop_interface.py` (80 lines)
  - `pressure_drop_calculator/__init__.py` (81 lines)
  - (plus the calculation engine)
- `calculate` — 7 definitions (various calculators)
- `fit` — 5 definitions (data processing modules)
- `generate` — 4 definitions
- `run_simulation` — 3 definitions (pendulum simulator variants)
- `filter` — 3 definitions in kalman_filter.py alone

### Impact

For `calculate_pressure_drop`, 4 independent implementations means 4 places to fix bugs and 4 places where physics constants could diverge. This is especially dangerous for a shared library where downstream repos depend on consistent results.

### Recommendation

1. Audit the 4 `calculate_pressure_drop` implementations for consistency
2. Consolidate to a single implementation with configuration parameters
3. The `pressure_drop_calculator/__init__.py` (304 lines of logic in init!) should delegate to the engine module
