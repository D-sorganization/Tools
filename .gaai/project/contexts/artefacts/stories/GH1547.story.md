# GH1547: Enforce required shared Python provider-contract suite in CI

**Source:** D-sorganization/Tools#1547

## Description

## Problem

The main Python workflow currently runs changed tests plus a small smoke subset. That is not sufficient for `src/shared/python` and other exported packages.

## Required Changes

- Add a required provider-contract test target for core exported packages:
  - `upstream_drift_tools`
  - `signal_toolkit`
  - `model_generation`
  - `theme`
  - other exported shared packages with downstream consumers
- Ensure shared-package changes trigger this suite automatically
- Remove reliance on `--cov-fail-under=0` for this path
- Report coverage and contract status specifically for exported packages

## Acceptance Criteria

- A breaking import or minimal-runtime regression in exported packages fails CI
- Shared-package changes always run provider-contract tests
- Contract coverage is visible in CI output

## Acceptance Criteria

1. The issue described in #1547 is resolved
2. All new code has tests (TDD)
3. `ruff check` passes on modified files
4. No new `print()` calls in `src/`
5. PR created targeting `staging` branch with clear description
