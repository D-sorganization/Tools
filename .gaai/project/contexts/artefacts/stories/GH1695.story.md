# GH1695: Assessment: cors.py import regression FIXED — but contracts not in requirements.txt

**Source:** D-sorganization/Tools#1695

## Description

## Assessment Category: K — Key Dependency (Import Chain)

**Severity:** Low — The import works, but the dependency chain is fragile.

### Finding

**cors.py import regression: RESOLVED.** The `cors.py` file imports `from contracts import require` which resolves correctly because `src/shared/python/contracts.py` provides the module. The import chain works:

```
cors.py -> contracts.require -> src/shared/python/contracts.py (local module)
```

**However:** The `contracts` module is NOT a pip package — it is a local module. This means:
1. It is NOT listed in `requirements.txt` or `pyproject.toml` dependencies
2. It only works when `src/shared/python` is on `sys.path` (set by pytest.ini's `pythonpath`)
3. If someone does `pip install ud-tools && from cors import add_cors_middleware`, it will fail unless they also install with the correct package layout

Additionally, 33 files import from `contracts` across the codebase. 10 files use `from src.shared.python.contracts import ...` (absolute path that depends on CWD) while others use `from contracts import ...` (relative, depends on sys.path).

### Recommendation

1. Ensure `contracts.py` is included in the package distribution via `[tool.setuptools.packages.find]`
2. Standardize import style: use `from contracts import ...` everywhere (not `from src.shared.python.contracts`)
