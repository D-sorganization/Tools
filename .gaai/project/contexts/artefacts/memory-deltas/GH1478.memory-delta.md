# GH1478 Memory Delta

## Pattern Observed

**Pattern: physics_native.py DbC strategy**

When fixing DbC violations in physics parameter constructors, use dictionary iteration over named parameters to avoid N-repeated `isinstance`/`ValueError` blocks:

```python
_lengths = {"l_hub": l_hub, "l_r_upper": l_r_upper, ...}
for name, val in _lengths.items():
    if not isinstance(val, (int, float)):
        raise TypeError(f"{name} must be a number, got {type(val).__name__}")
    if val <= 0:
        raise ValueError(f"{name} must be positive, got {val}")
```

This DRY pattern scales well for constructors with 10+ parameters.

## LoD Assessment Note

The adversarial assessment scanner flags `sys.path.insert(0, ...)` and `os.path.abspath(...)` as LoD violations, but these are 2-level chains (compliant with the >2-level rule). The genuine violation is `pathlib.Path(__file__).resolve().parent` (3-level: `.resolve()` then `.parent`). Extraction to an intermediate variable resolves it.

PyQt signal patterns like `button.clicked.connect(handler)` are NOT LoD violations — `.clicked.connect` is 2-level.
