# GH1695 Memory Delta

## New Patterns Worth Persisting

### Pattern: Python module-identity requires consistent import paths

**Domain:** Python packaging, import system, test infrastructure
**Signal:** High — will recur whenever a bare module (no __init__.py) is imported via two different paths

**Description:**
When Python imports the same `.py` file via two different module path strings
(e.g., `contracts` vs `src.shared.python.contracts`), it creates TWO separate module
objects. Exceptions, classes, and other objects from one are not identity-equal to
those from the other. This causes `pytest.raises(ExceptionClass)` to silently miss
exceptions from the other path.

**Rule:**
When standardizing imports in `src/` files, the corresponding `tests/` files MUST also
be updated to use the same import path — otherwise DBC test assertions silently fail.

**Anti-pattern:**
```python
# src/tools/launch_utils.py
from contracts import require  # short form

# tests/tools/test_launch_utils.py
from src.shared.python.contracts import PreconditionError  # absolute form
# → pytest.raises(PreconditionError) WILL NOT catch contracts.PreconditionError
```

**Correct pattern:**
Both src/ and tests/ must use the same import path for the same module.

### Pattern: Bare modules in setuptools require py-modules declaration

**Domain:** Python packaging, pyproject.toml
**Signal:** Medium — any new bare .py module added to src/shared/python/ needs this

**Description:**
`[tool.setuptools.packages.find]` only discovers Python *packages* (directories with
`__init__.py`). Bare `.py` files like `contracts.py`, `cors.py` are NOT included
automatically and must be listed in `[tool.setuptools] py-modules`.

**Rule:**
When adding a new bare `.py` module to `src/shared/python/`, add it to the
`py-modules` list in `pyproject.toml`'s `[tool.setuptools]` section.
