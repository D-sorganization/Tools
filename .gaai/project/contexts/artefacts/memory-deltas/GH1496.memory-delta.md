# GH1496: Memory Delta

## Pattern: DbC Migration from assert to TypeError/ValueError

When converting `assert x is not None` to proper DbC, the pattern is:

```python
# Before (DbC violation — AssertionError, not TypeError)
assert expression is not None, "expression must be provided"

# After (DbC compliant)
if not isinstance(expression, str):
    raise TypeError("expression must be a string")
if not expression:
    raise ValueError("expression must be a non-empty string")
```

Key insight: `assert` statements raise `AssertionError`, not `TypeError`. CLAUDE.md requires `TypeError` for wrong types. This is a systematic distinction the DbC checker is flagging.

## Pattern: LoD Fix for Matrix Subscript Access

When a tool flags `skew[2, 1]` or `transform[:3, :3]` as LoD violations, the fix is to extract subscript accesses to named locals before use:

```python
# Before
return sp.Matrix([skew[2, 1], skew[0, 2], skew[1, 0]])

# After
elem_21 = skew[2, 1]
elem_02 = skew[0, 2]
elem_10 = skew[1, 0]
return sp.Matrix([elem_21, elem_02, elem_10])
```
