# GH1649 Memory Delta — Refactor Oversized Files

## Pattern: Private-submodule + re-export shim

When a Python module exceeds the 1200-line budget:
1. Create private submodules named `_{module}_{domain}.py` in the same package
2. Move cohesive function groups into each submodule
3. Rewrite the original file as a thin re-export shim with `__all__`
4. Downstream imports from the original module path are unaffected

This pattern was applied to:
- `rotation_converter/modern_robotics.py` → `_mr_rotation_matrices.py`, `_mr_kinematics.py`, `_mr_dynamics.py`
- `pressure_drop_calculator/pressure_drop_interface.py` → `_pdi_helpers.py`, `_pdi_formatters.py`

## Pattern: Import DAG discipline

For packages with multiple private submodules, enforce a strict dependency order to prevent circular imports:
```
level-0: no intra-package deps (pure math/primitives)
level-1: imports from level-0 only
level-2: imports from level-0 only (NOT level-1, even if logically adjacent)
shim:    imports from all levels, re-exports everything
```

`_mr_dynamics.py` was implemented to import only from `_mr_rotation_matrices` (level-0), not from `_mr_kinematics` (level-1), even though both relate to robot mechanics. This avoided a potential circular import and kept the DAG clean.

## Pattern: `_wrap_text` cross-dependency

When splitting a monolith into formatters/helpers/core layers, utility functions used by both "core" and "formatters" should live in the formatters module and be imported back into core as needed:
```python
from pressure_drop_calculator._pdi_formatters import _wrap_text
```
