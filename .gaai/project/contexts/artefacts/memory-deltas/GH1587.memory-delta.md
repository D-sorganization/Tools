## Patterns Worth Persisting

### Pattern: Test coverage gap analysis methodology

When a story reports "N modules have no test file" based on name-matching, the actual
gap is often much smaller because:
1. Tests may live in a separate `tests/` directory with differently-named files
2. Tests may be embedded in `src/` subdirectories (`tests/` sub-packages)
3. Name-matching by `test_<module>.py` misses tests for the same module under alt names

**Recommendation:** Before delivering a test-coverage story, do a proper reverse lookup:
for each source module, check all known test directories for any test importing that module,
not just `test_<module>.py` by name.

### Pattern: Shared library test priority

For a shared library consumed by downstream repos (UpstreamDrift, Gasification_Model),
priority for adding missing tests should be:
1. Pure-math modules with known analytical solutions (highest ROI, verifiable)
2. Public API contract modules (Pydantic models, interfaces)
3. Complex modules with external deps — defer to focused stories
