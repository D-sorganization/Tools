# GH1488 Memory Delta

## Pattern: PyQt6 Sub-Project Test Setup

**Context:** Multiple `src/*/python/` sub-projects follow a nested package layout. Tests for these sub-projects require a `conftest.py` at the sub-project root to add `python/` to `sys.path`.

**Established pattern (urdf_builder_gui, steam_engine_calculator):**
```python
# conftest.py at src/<module>/
import sys
from pathlib import Path

_python_dir = str(Path(__file__).resolve().parent / "python")
if _python_dir not in sys.path:
    sys.path.insert(0, _python_dir)
```

**Action for Discovery:** When processing adversarial assessment stories for sub-projects with `python/` subdirectory structure, check for missing `conftest.py` before writing the story. This is a prerequisite for tests to be runnable.

## Pattern: PyQt6 Mock for Headless Tests

When mocking PyQt6 for headless tests of modules that inherit from `BaseCalculatorWindow`, the mock must include `upstream_drift_tools` modules in addition to PyQt6:

```python
with patch.dict(sys.modules, {
    "PyQt6": MagicMock(),
    "PyQt6.QtCore": mock_qt_core,  # with concrete enum values
    "PyQt6.QtGui": mock_qt_gui,    # with concrete enum values
    "PyQt6.QtWidgets": MagicMock(),
    "upstream_drift_tools": MagicMock(),
    "upstream_drift_tools.ui": MagicMock(),
    "upstream_drift_tools.ui.widgets": MagicMock(),
    "upstream_drift_tools.ui.widgets.base_calculator_widget": mock_base_module,
}):
```

**Reason:** `BaseCalculatorWindow` mixin chain imports Qt at class definition time, causing metaclass conflict if the mock is partial.

## Pattern: Testing DbC on Instance Methods Without Instantiation

For PyQt6 window methods where `__init__` triggers full Qt setup, test preconditions by calling the unbound method with a `MagicMock` as `self`. The precondition check raises before any Qt interaction:

```python
fake_self = MagicMock()
with pytest.raises(TypeError, match="..."):
    ClassName._method(fake_self, invalid_arg)
```

This avoids the need to instantiate the full window in tests.
