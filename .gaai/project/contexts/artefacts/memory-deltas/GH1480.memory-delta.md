# Memory Delta: GH1480

## Pattern: Conditional Import Guard Conflicts with LoD Fix

**Context:** `src/pressure_drop_calculator` and `src/function_generator` both use `if os.environ.get("HEADLESS", "false").lower() == "true":` as a guard before conditional matplotlib backend setup. This guard precedes module-level imports.

**Finding:** Extracting the `os.environ.get(...)` call to a module-level variable to fix the LoD chain triggers ruff E402 ("Module level import not at top of file") on all subsequent imports. The only compliant workaround would be adding `# noqa: E402` to every subsequent import line.

**Decision:** For PyQt6 GUI modules that use the headless conditional import pattern, the `os.environ.get(...).lower()` chain is an acceptable exception to the LoD rule. The ruff E402 constraint takes precedence (AC3). This is consistent with the established pattern in `function_generator`.

**Implication for future stories:** When fixing LoD violations in GUI modules with headless guards, document this exception rather than attempting to extract the assignment (which creates ruff violations).
