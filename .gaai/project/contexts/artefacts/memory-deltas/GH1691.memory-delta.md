# GH1691 Memory Delta

## New Patterns Established

### 1. Private JAX Helper Extraction Pattern

**Context**: `physics_golfer_jax.py` and similar JAX physics files.

**Pattern**: When a JAX function exceeds 100L due to repetitive per-body computation
(Jacobians, FK positions), extract per-body groups into pure private helpers:
- Accept explicit precomputed sin/cos values and `GolferParamsJAX` as parameters
- Return a `dict` (for Jacobian groups) or `tuple` (for position groups)
- All helpers remain pure functions compatible with `jit` and `vmap`
- Use `.at[].set()` for JAX array operations (no in-place mutation)

**Files**: `physics_golfer_jax.py`
**New helpers**: `_right_arm_jacobians_jax`, `_left_arm_jacobians_jax`, `_club_jacobians_jax`,
`_right_arm_fk_jax`, `_left_arm_fk_jax`, `_club_fk_jax`

### 2. Multi-Return Doc Setup Helper Pattern

**Context**: `programmatic_pid/cli.py` DXF sheet generators.

**Pattern**: When multiple sheet-generator functions share the same document setup
(ezdxf new, ensure_layers, layer_index resolution, text config, layout computation),
extract into a `_setup_*_doc(spec)` helper returning a multi-element tuple.
Callers unpack the tuple explicitly.

**Files**: `cli.py`
**New helper**: `_setup_process_doc(spec) -> 10-tuple`

### 3. Panel Builder Signal Extraction Pattern

**Context**: `panel_builders.py` wire_toolstrip function.

**Pattern**: Signal connection blocks in `wire_toolstrip` that capture `main_window`
via a closure can be extracted into module-level helpers that accept `active_panel_fn`
as a callable parameter. This avoids capturing the entire window object.

**Files**: `panel_builders.py`
**New helper**: `_wire_overlay_signals(ts, active_panel_fn)`

## Patterns Reinforced

- **GH1650 perturbation extraction pattern**: Used again for `_wire_double/triple/golfer_perturbation`
- **Private plotting helper**: matplotlib try/except block extracted to `_simulate_control_plot`

## Discovery Flags

None — all patterns are internal to existing modules. No new public APIs introduced.
No downstream (UpstreamDrift, Gasification_Model) impact.
