# GH1546 Memory Delta

## New Patterns

### Pattern: Cross-Repo Python Integration Workflow

**Location:** `.github/workflows/cross-repo-python-integration.yml`

**Pattern:** GitHub Actions matrix workflow that validates shared Python packages against downstream consumers. Key design decisions:
- Matrix strategy per downstream repo (fail-fast: false to test all consumers)
- `continue-on-error: true` on downstream checkout — graceful skip if repo inaccessible
- Suite availability check before running tests — skips with informative message if `tests/shared_contracts/` not yet present in downstream
- Symlink approach (`ln -sfn`) to make current Tools branch available to downstream tests without installing as a package
- PYTHONPATH injection to expose shared Python packages to downstream test runner

**Trigger pattern for cross-repo workflows:**
```yaml
on:
  push:
    branches: [main, staging]
    paths:
      - "src/shared/python/**"
      - "src/python/**"
      - "manifests/**"
  pull_request:
    branches: [staging, main]
    paths:
      - "src/shared/python/**"
      - "src/python/**"
      - "manifests/**"
```

### Pattern: Contract Category Enumeration in Summary

The Summary step should enumerate contract test files to help identify which contract category failed:
```bash
find tests/shared_contracts -name "test_*.py" -o -name "*_test.py" 2>/dev/null | sort | while read -r f; do
  echo "- \`$f\`" >> "$GITHUB_STEP_SUMMARY"
done
```
