# Memory Delta — GH1694

## Patterns Worth Persisting

### Pattern: defusedxml dual-import cleanup

**Context:** When a module imports both `xml.etree.ElementTree as ET` and `defusedxml.ElementTree as DefusedET`, and ET is used only for type hints + exception handling (not for any runtime parsing), the stdlib ET import should be moved to a `TYPE_CHECKING` guard.

**Rule:**
```python
from __future__ import annotations
from typing import TYPE_CHECKING

import defusedxml.ElementTree as DefusedET

if TYPE_CHECKING:
    import xml.etree.ElementTree as ET  # only for type hints
```

This pattern is enabled by `from __future__ import annotations` (PEP 563 deferred evaluation), which makes function-signature annotations strings at runtime, removing the need for the actual ET class at import time.

**Exception:** If the module uses ET for the write path (ET.Element, ET.SubElement, ET.tostring), the stdlib import must remain at the top level. This is safe — these operations construct trusted output, not parse untrusted input.

### Pattern: DefusedET.ParseError for catch-sites

When catching XML parse errors from a defusedxml parse call, prefer:
```python
except DefusedET.ParseError as e:
```
over:
```python
except ET.ParseError as e:
```

`DefusedET.ParseError` is the same class as `ET.ParseError` (re-exported), but using it makes the catch-site anchored to the defusedxml import, clarifying the intent.

Note: defusedxml raises `defusedxml.common.EntitiesForbidden` (subclass of `ValueError`) for XXE/DTD attacks — this is NOT caught by ParseError. The two error types are complementary.
