# Memory Delta: GH1697

## New Patterns Worth Persisting

### Pattern: Non-blocking nightly full-repo quality audit

When the delta-CI approach creates a ratchet accumulation problem (violations never caught
in untouched files), the established pattern is to add a weekly scheduled GitHub Actions job
using `continue-on-error: true` at the step level. This job:
- Never fails CI (informational only)
- Reports violation counts in GITHUB_STEP_SUMMARY
- Runs weekly Sunday 3 AM UTC (cron: "0 3 * * 0")

See: `.github/workflows/nightly-full-repo-quality.yml` (GH1697) and existing `Code-Metrics.yml`.

### Pattern: T201 per-file-ignores for CLI scripts

When adding T201 (print detection) to ruff.toml, root-level launcher scripts (`launch.py`,
`verify_launcher.py`) and test files (`tests/**/*.py`) must be added to per-file-ignores
to prevent false-positive delta CI failures on legitimate print() use.
