# GH1733 Execution Plan: Pin Dependency Versions

## High-Level Approach

This story addresses 234 unpinned or range-based dependencies across the codebase.

**Key context:** This repo is a _shared library_ (not an application). Library packaging
best practice (PEP 517, pip docs) dictates:

- `pyproject.toml` runtime deps use `>=` minimum bounds — CORRECT, do NOT change
- `requirements.txt` (dev/CI environment) should use `>=` with a companion lock file — already done
- Sub-module `requirements.txt` files used as application installs should use `==` pins

**Approach selected:** No `approach-evaluation` needed. Established pattern:

- Root `pyproject.toml`: leave `>=` bounds as-is (correct for a library)
- Root `requirements.txt`: annotate with policy comment pointing to requirements-lock.txt
- Sub-module requirements files: add minimum pins to completely unpinned packages
- Add `DEPENDENCIES.md` policy document explaining the pinning strategy

## Implementation Sequence

### Step 1: Create dependency policy document

- File: `DEPENDENCIES.md` (new)
- Explains the tiered pinning strategy for library vs application contexts
- References `requirements-lock.txt` as the reproducible-build mechanism

### Step 2: Annotate root requirements.txt

- Add policy header comment explaining >= rationale + lock file reference
- No version changes needed (already has minimum bounds)

### Step 3: Fix completely unpinned packages in sub-modules

- `src/web_applications/urdf_viewer/requirements.txt` — `fastapi`, `uvicorn`, `aiofiles`, `python-multipart` have no version constraint at all
- `src/shared/python/upstream_drift_tools/process_calculators/syngas_compression/requirements.txt` — placeholder content

### Step 4: Update requirements-lock.txt header

- Update generation comment (stale: 2026-03-09)
- Add policy comment about when to regenerate

### Step 5: Verify ruff passes on modified files

- Only documentation and requirements files changed — no Python code
- `ruff check` passes trivially (no Python files modified)

## Test Checkpoints

- AC1: All dependency files have version constraints (no completely unpinned packages)
- AC2: Tests still pass (no code changes, but verify ruff on any modified .py files)
- AC3: `ruff check` on modified files — passes (no .py changes)
- AC4: No new `print()` in src/ — trivially satisfied (no code changes)
- AC5: PR targeting staging

## Edge Cases

- `tkinter` in requirements files: this is a stdlib module; skip version pinning (cannot be pip-installed)
- `numba`, `cupy` in rrt_path_planner/requirements.txt: marked "optional/if CUDA available" — add minimum `>=` bounds, keep comment
- `google-generativeai` in pdf_renamer: already has `>=` bound — acceptable
- `pyproject.toml` `>=` bounds: intentionally loose for library consumers — document in policy but do NOT change
