### LoD Violations in `launch_rrt_asteroid_navigator.py`

Line 24-25 contains a 6-level path chain that violates LoD (max 2 levels):
```python
PYTHON_SRC = (
    REPO_ROOT / "src" / "scientific_modeling" / "rrt_path_planner" / "python" / "src"
)
```

Additionally, `"scientific_modeling"` no longer exists — the directory was flattened.

Fix: Break into intermediate variables with at most 2 levels each, and correct the path.

```python
_RRT_ROOT = REPO_ROOT / "src" / "rrt_path_planner"
PYTHON_SRC = _RRT_ROOT / "python" / "src"
```

## Implementation Sequence

### Step 1: Fix LoD in `launch_rrt_asteroid_navigator.py`

Replace lines 24-26:
```python
PYTHON_SRC = (
    REPO_ROOT / "src" / "scientific_modeling" / "rrt_path_planner" / "python" / "src"
)
```
With:
```python
_RRT_ROOT = REPO_ROOT / "src" / "rrt_path_planner"
PYTHON_SRC = _RRT_ROOT / "python" / "src"
```

This breaks the 6-level chain into two 2-level operations and corrects the path.

### Step 2: Fix DbC violations in `star_wars_rrt.py`

Replace all `assert ... is not None, "..."` patterns with explicit `raise TypeError(...)`.
Pattern:
```python
# Before
assert point is not None, "point must be provided"

# After
if point is None:
    raise TypeError("point must not be None")
```

For typed arguments (`int`, `str`), use `isinstance` checks:
```python
# Before
assert width is not None, "width must be provided"

# After
if not isinstance(width, int) or width <= 0:
    raise TypeError("width must be a positive int")
```

Note: `format_metrics` has no assert (already correct). Renderer methods with visualization
guards (`if not PYGAME_AVAILABLE`) keep their runtime guard and gain the new TypeError checks.

### Step 3: Update/extend tests

The existing `python/tests/test_star_wars_rrt.py` (unittest) tests DbC contracts but
expects the old `AssertionError` (from `assert`). Update tests to expect `TypeError` instead.

Also add tests for `None`-input paths to cover the new `raise TypeError` paths:
- `distance_to_obstacle_surface(None, obstacle)` → `TypeError`
- `generate_asteroid_field(None, 5)` → `TypeError`
- `RRTPlanner(None)` → `TypeError`
- `planner.plan_path(None, goal, [])` → `TypeError`
- `planner.analyze_path(None, [])` → `TypeError`
- `planner.smooth_path(None, [])` → `TypeError`
- `PursuitAI(None)` → `TypeError`

These tests live in the existing `python/tests/test_star_wars_rrt.py`.

## Edge Cases

- `StarWarsRenderer` methods: only called at runtime with visualization libs. Tests for
  these are skipped if `pygame`/`OpenGL` unavailable — that is pre-existing behavior.
- `_steer`, `_segment_is_collision_free`, `_render_*`: internal methods. Adding TypeError
  on None for `None`-valued arguments is consistent with DbC policy.
- `del obstacles` in `update_target_behavior`: keep the `del` — it's an intentional
  discard, not a LoD issue.
