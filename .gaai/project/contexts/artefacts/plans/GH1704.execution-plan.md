# GH1704 Execution Plan — DbC Enforcement Consistency

## Summary

Two categories of changes:

1. **Fix `_handle_violation` in `contracts.py`** — replace module-level alias reads (`DBC_LEVEL`) with direct `_ContractState.level` reads. Removes the stale-alias risk entirely, makes enforcement dynamic without relying on `sys.modules` patching.

2. **Add precondition contracts to `scrubber_calculator.py` public functions** that accept physical values (temperature_k, pressure_pa, molecular_weight, etc.). Add one `ensure()` postcondition to `calculate_gas_density`. Import `require`, `ensure`, `check_temperature`, `check_pressure`, `check_positive` from `contracts`.

3. **Add contract-violation tests** to `tests/shared/python/process_calculators/test_scrubber_calculator.py` covering the new preconditions.

---

## Implementation Sequence

### Step 1: Fix `_handle_violation` in `contracts.py`

File: `src/shared/python/contracts.py`

Change `_handle_violation`, `require`, `ensure`, `invariant` to read `_ContractState.level` directly instead of the `DBC_LEVEL` module alias.

This eliminates the identified stale-alias issue — `_ContractState.level` is always current.

### Step 2: Add preconditions to `scrubber_calculator.py`

File: `src/shared/python/upstream_drift_tools/process_calculators/scrubber_calculator.py`

Add import: `from contracts import require, ensure, check_temperature, check_pressure, check_positive, check_non_negative`

Add `require()` calls to:
- `calculate_gas_density(temperature_k, pressure_pa, molecular_weight)` — all three must be positive
- `calculate_gas_viscosity(temperature_k, molecular_weight)` — both must be positive
- `calculate_flooding_velocity(liquid_mass_flux, gas_density, liquid_density, ...)` — densities must be positive
- `calculate_pressure_drop(gas_velocity, gas_density, ...)` — physical values must be non-negative/positive
- `calculate_ntu_removal(inlet_conc, outlet_conc)` — inlet must be > 0
- `calculate_caustic_requirement(...)` — flow rates must be positive
- `calculate_heat_transfer_duty(...)` — temperatures and flows must be reasonable
- `calculate_column_diameter(...)` — velocities must be positive

Add `ensure()` postcondition to `calculate_gas_density` — result must be positive.

Replace ad-hoc `assert foo is not None` guards with proper `require()` calls where present.

### Step 3: Add tests for contract enforcement

File: `tests/shared/python/process_calculators/test_scrubber_calculator.py`

Add a `TestScrubberCalculatorContracts` class with:
- `test_gas_density_negative_temperature_raises` — verify `PreconditionError` when temperature_k <= 0
- `test_gas_density_negative_pressure_raises` — verify `PreconditionError` when pressure_pa <= 0
- `test_gas_density_negative_mw_raises` — verify `PreconditionError` when molecular_weight <= 0
- `test_gas_viscosity_negative_temperature_raises` — verify `PreconditionError`
- `test_flooding_velocity_negative_gas_density_raises` — verify `PreconditionError`
- `test_contracts_off_skips_checks` — verify no raise when `DBC_LEVEL=OFF`

Import `PreconditionError` from `contracts` and use `set_contract_level(ContractLevel.ENFORCE)` fixture.

## Edge Cases

- The `assert foo is not None` guards in scrubber_calculator are not DbC-compliant (bypass when Python is run with `-O`). Replace with `require()` which is level-controlled.
- The `calculate_flooding_velocity` already guards `gas_density > 0` in division — but silently returns 0.0. Adding a precondition makes this explicit.
- `check_temperature` checks `> 0 K`, which is appropriate for absolute temperature. `pressure_pa` uses `check_pressure` (`> 0`).
- The `contracts.py` fix to use `_ContractState.level` is backward-compatible — `set_contract_level` still updates `_ContractState.level` as before.
