# GH1495 Execution Plan

## Story Summary

Address TDD, DRY, DbC, and LoD violations in `src/vessel_drafter`.

## Pre-Analysis Findings

- DbC violations in `step_export.py`, `vessel_export.py`, `material_summary_table.py` were already
  fixed by PR #1500 (`fix(lod): Address DbC and LoD in Tools modules`).
- Remaining LoD violations require extraction of intermediate attributes into local variables.
- No existing test files for vessel_drafter modules in `tests/`.

## Remaining Violations

### LoD — `vessel_drafter_metrics.py` lines 68, 70

`component.shape.volume` and `component.shape.area` — 2-level chains.
Fix: `shape = component.shape` then use `shape.volume` and `shape.area`.

### LoD — `step_export.py` (multiple)

`output_path.parent.mkdir(...)` and `manifest_path.parent.mkdir(...)` in three functions.
Fix: `output_dir = output_path.parent; output_dir.mkdir(...)` etc.

### LoD — `cli.py` lines 81, 89, 97

`sys.stdout.write(str(step_path) + "\n")` — `sys.stdout` is 2-level access.
Fix: `stdout = sys.stdout; stdout.write(str(step_path) + "\n")`.

## Implementation Sequence

### Step 1: Fix `vessel_drafter_metrics.py`
- Extract `shape = component.shape` in `_component_metric`
- Use `shape.volume` and `shape.area`

### Step 2: Fix `step_export.py`
- In each of three export functions, extract `output_path.parent` and `manifest_path.parent`
  into local variables before calling `.mkdir()`

### Step 3: Fix `cli.py`
- In `main()`, assign `stdout = sys.stdout` and use `stdout.write(...)` in each branch

### Step 4: Write tests
- Create `tests/vessel_drafter/` directory
- Write `test_vessel_drafter_dbc_lod.py` covering:
  - DbC: TypeError/ValueError on bad inputs for all public functions with guards
  - LoD: functions still work correctly after refactor (regression tests)
  - All new tests marked `@pytest.mark.unit`

### Step 5: Quality gates
- `ruff check` on all modified files
- `ruff format --check` on all modified files
- Run new tests

## Edge Cases

- `output_path` with existing parent directory — must not fail
- Type checking: use `isinstance` raises not bare `assert` for production DbC

## Test Checkpoints

- All LoD fixes maintain identical behavior (regression coverage)
- DbC assertions fire correctly on None inputs
