# GH1657 Execution Plan: Centralize configuration with XDG Base Directory support

## Summary

Add `get_xdg_config_dir(app_name)` to `src/python/src/utils/config_loader.py` to return
an XDG-compliant config directory (`$XDG_CONFIG_HOME/<app_name>` on Linux, platform-appropriate
equivalents on macOS/Windows). Fix folder_tool's hardcoded log path in `Folders_Tool_r0.py`
to use this function. Add tests.

## Implementation Sequence

### Step 1 — Add XDG helper to config_loader.py
File: `src/python/src/utils/config_loader.py`

Add function `get_xdg_config_dir(app_name: str) -> Path` that:
- Checks `$XDG_CONFIG_HOME` env var; uses it if set
- Falls back to `~/.config/<app_name>` on Linux/macOS
- Falls back to `%APPDATA%/<app_name>` on Windows (via `$APPDATA` env var)
- Returns a `Path` object (does NOT create the directory — caller decides)
- Validates: `TypeError` if `app_name` not str, `ValueError` if empty

### Step 2 — Fix hardcoded log path in Folders_Tool_r0.py
File: `src/folder_tool/Folders_Tool_r0.py`

Replace hardcoded `log_filename = "folder_processor.log"` with XDG-aware path using
`get_xdg_config_dir("folder_tool")`. Import the function from shared utils if possible;
if import fails (bootstrap environment), fall back to `Path.home() / ".config" / "folder_tool"`.

### Step 3 — Write tests
File: `tests/folder_tool/test_xdg_config.py` (new)
File: `tests/test_config_loader.py` (add XDG tests to existing)

Tests:
- `get_xdg_config_dir("myapp")` returns Path ending in `myapp`
- Respects `$XDG_CONFIG_HOME` env override
- Falls back to `~/.config/myapp` when `$XDG_CONFIG_HOME` not set (Linux/macOS)
- TypeError on non-string app_name
- ValueError on empty app_name

## Edge Cases
- Windows: `$APPDATA` may not be set in CI; graceful fallback to `~/.config`
- Import failure in bootstrap context: graceful fallback
- app_name with path separators: reject with ValueError
