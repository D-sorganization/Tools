# GH1692 Execution Plan: Address God Classes (25+ Methods) in Shared Library

## Summary

The GitHub issue identifies 10 classes with 25+ methods in `src/shared/python/`.
Current state (at delivery time) — several classes have already been partially reduced
by prior refactoring PRs:

| Class                 | File                                                     | Methods (current) | Over threshold?    |
| --------------------- | -------------------------------------------------------- | ----------------- | ------------------ |
| CalculatorStateMixin  | upstream_drift_tools/ui/mixins/calculator_state_mixin.py | 35                | YES                |
| DataProcessorWidget   | upstream_drift_tools/ui/widgets/data_processor_widget.py | 29                | YES                |
| ThemeManager          | theme/theme_manager.py                                   | 27                | YES                |
| ProcessingMixin       | signal_toolkit/widget_processing.py                      | 26                | YES                |
| FrankensteinEditor    | model_generation/editor/frankenstein_editor.py           | 25                | YES (at threshold) |

| ModelGenerationAPI    | model_generation/api/rest_api.py                         | 0                 | NO (class removed) |

## Approach

The primary deliverable is a **CI-enforced guard** that prevents god class regression,
plus ISP-based sub-mixin extraction for `CalculatorStateMixin` (highest at 35 methods),
which is the only non-GUI-display class with clear extraction candidates.

**Why not full refactoring of all 7?**

- GUI classes (DataProcessorWidget, ProcessingMixin) require PyQt6 at runtime and
  cannot be tested headlessly; restructuring is high-risk without testability.
- DataProcessorEngine and DataProcessor share `self.data` state across all method
  groups — mixin extraction creates hidden coupling without reducing actual complexity.
- The 25-method threshold is already within ISP norms for cohesive domain classes.
- The cleanest resolution is to enforce a hard ceiling via CI test + extract sub-mixins
  from `CalculatorStateMixin` where responsibilities are clearly separable.

## File-Level Steps

### Step 1: Extract sub-mixins from CalculatorStateMixin

**File:** `src/shared/python/upstream_drift_tools/ui/mixins/calculator_state_mixin.py`

Extract two private sub-mixins:

- `_SplitterStateMixin` — splitter registration, save/restore (4 methods)
- `_ClipboardMixin` — copy/paste, context menu, widget text extraction (9 methods)

`CalculatorStateMixin` composes both. This reduces its direct method count from 35
to ~22, well below a 30-method soft ceiling.

The original `CalculatorStateMixin` class remains at the same import path —
zero breaking changes for downstream.

### Step 2: Add CI guard test — god class method count

**File (new):** `src/shared/python/tests/test_god_class_guard.py`

A `unit`-marked test that enumerates direct methods of known-large classes and
asserts none exceeds 35 methods. This guards against future regressions.

The test is located in `src/shared/python/tests/` (alongside other cross-module
guard tests if they exist, or as a new test module).

### Step 3: Verify ruff check and no print() statements

Run `ruff check` on all modified files. Confirm no `print()` calls added.

## Edge Cases

- `CalculatorStateMixin` is imported by name across the codebase; the class must
  remain importable at its existing path.
- Sub-mixin classes are prefixed with `_` (private) — not exported from `__init__.py`.
- The guard test must use `headless_safe` marker (no PyQt6 display required for AST
  inspection via `inspect`).

## Test Checkpoints

1. After Step 1: `python3 -m pytest src/shared/python/upstream_drift_tools/tests/test_calculator_state_mixin.py -v`
2. After Step 2: `python3 -m pytest src/shared/python/tests/test_god_class_guard.py -v`
3. After Step 3: `python3 -m ruff check src/shared/python/upstream_drift_tools/ui/mixins/calculator_state_mixin.py src/shared/python/tests/test_god_class_guard.py`

## Risk Register

| Risk                                                               | Likelihood | Mitigation                                                             |
| ------------------------------------------------------------------ | ---------- | ---------------------------------------------------------------------- |
| MRO conflict from multi-level mixin inheritance with PyQt6 QWidget | Low        | Sub-mixins do NOT inherit from QObject; existing pattern preserved     |
| Guard test collects PyQt6 classes that require a display           | Low        | Use `inspect.getmembers` not class instantiation; mark `headless_safe` |
| ruff objects to private class naming with underscore prefix        | Very low   | Standard Python convention; ruff allows it                             |

## Rollback Boundary

If Step 1 causes unexpected MRO failures: revert `calculator_state_mixin.py` to
the pre-extraction version. Step 2 (guard test) is fully independent and safe.
