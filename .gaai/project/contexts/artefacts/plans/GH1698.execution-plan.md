# GH1698 Execution Plan — noqa Suppression Audit

## Goal

Remove stale `# noqa` suppressions from `src/`. A suppression is "stale" when the rule it suppresses is not in the enabled rule set and the directive serves no purpose — caught by `RUF100` (unused-noqa).

## Approach Rationale

`ruff` provides first-class support for detecting and auto-fixing stale `noqa` directives via
`RUF100` (unused-noqa). The `--fix` flag removes them automatically without risk of introducing
new violations, because it only removes comments — no logic changes.

This is the canonical ruff approach. No alternative approaches evaluated (single viable path).

## Implementation Sequence

### Step 1: Baseline snapshot
- Run `ruff check src/ --select RUF100 --output-format concise` to capture pre-fix count
- Expected: 183 violations across 80 files

### Step 2: Auto-fix all stale suppressions
- Run `ruff check src/ --select RUF100 --fix`
- This removes noqa comments where the suppressed rule code is not enabled

### Step 3: Verify zero RUF100 violations remain
- Run `ruff check src/ --select RUF100` — expect zero

### Step 4: Run standard ruff check to confirm no regressions
- Run `ruff check src/` — expect zero new violations beyond pre-existing baseline

### Step 5: Run ruff format check to confirm no formatting regressions
- Run `ruff format --check src/` — expect zero diffs

## Edge Cases

- **Noqa with multiple codes** (e.g., `# noqa: S603, S607`): ruff RUF100 handles partial removal
  correctly — removes only the unused code from the list, not the entire directive if any code
  in the list is still needed.
- **`# noqa` bare (no code)**: bare noqa directives suppressing all rules — if the line has no
  violations, RUF100 flags the entire directive. The fix removes the bare comment.
- **Files in ruff exclude list**: excluded files are skipped by ruff — no changes made to them.

## Test Checkpoints

- AC3: `ruff check` on modified files passes (zero new violations)
- AC4: No new `print()` calls (no logic changes — this is guaranteed as we only remove comments)
- AC5: PR created targeting `staging` branch

## Risk Register

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| noqa was suppressing a real future violation | Low | We only remove suppressions for DISABLED rules; if the rule isn't selected, the suppression has no effect |
| Partial removal from multi-code noqa | Low | RUF100 --fix handles this correctly |
| Breaking changes to downstream repos | None | Only removing comments, no logic/API changes |

## Rollback Boundary

Changes are comment-only. Git revert is trivial. No logic changes made.

## Files Affected

80 files in `src/` — full list in RUF100 output. All changes are `# noqa` comment removals only.
