# Execution Plan: GH1653 — Add cross-repo integration test for UpstreamDrift/Gasification compatibility

## Summary

Create a dedicated integration test module that verifies all public API symbols
from the `upstream_drift_tools` package are importable and structurally sound,
simulating what UpstreamDrift and Gasification_Model do at import time.

## Approach

Approach follows existing conventions in `tests/` directory. No new libraries
introduced. Uses `@pytest.mark.integration` marker (already registered in
pyproject.toml). Single new test file approach.

## Implementation Sequence

### Step 1 — Create test file

**File:** `tests/test_cross_repo_import_compatibility.py`

Content:
1. Module docstring explaining purpose: verifies downstream repo import surface
2. `@pytest.mark.integration` marker on each test class
3. `TestUpstreamDriftToolsImport` — verifies top-level package import works and exports correct symbols
4. `TestProtocolsContract` — verifies Calculator, ProcessCalculator, DataTransformer, StateSerializable, UnitConverter protocols are importable and runtime-checkable
5. `TestCalculationDataClasses` — verifies CalculationResult and ValidationResult have correct fields and defaults
6. `TestCalculatorsSubpackage` — verifies `upstream_drift_tools.calculators` and `BaseCalculationEngine` import
7. `TestDataProcessingSubpackage` — verifies `upstream_drift_tools.data_processing` subpackage importable
8. `TestInputValidatorContract` — verifies InputValidator methods match expected API (require_positive, require_in_range, require_keys, validate_temperature, validate_pressure, validate_composition)
9. `TestPackageVersion` — verifies `__version__` attribute is present and a non-empty string

### Step 2 — Verify markers registered

Check `pyproject.toml` — `integration` marker already registered. No change needed.

### Step 3 — Run QA checks

- `ruff check tests/test_cross_repo_import_compatibility.py` — zero violations
- `ruff format --check tests/test_cross_repo_import_compatibility.py` — zero diffs
- `python3 -m pytest tests/test_cross_repo_import_compatibility.py -v` — all pass

## Edge Cases

- `data_processing` subpackage may have heavy optional dependencies (scipy, pandas) — tests must not import them directly; only test the subpackage namespace importability
- `ui` subpackage requires PyQt6 — skip or guard with `pytest.importorskip`
- `theme` subpackage requires PyQt6 — same guard
- `lab` subpackage may have optional C3D deps — guard

## Test Checkpoints

| Step | Check | Expected |
|------|-------|----------|
| Import package | `import upstream_drift_tools` | No ImportError |
| Protocols | `from upstream_drift_tools import Calculator` | Succeeds |
| Data classes | `CalculationResult().values == {}` | True |
| Calculators | `from upstream_drift_tools.calculators import BaseCalculationEngine` | Succeeds |
| InputValidator | `InputValidator.require_positive("x", 1.0)` | No exception |
| InputValidator bad input | `InputValidator.require_positive("x", -1.0)` | Raises ValueError |

## Risk Register

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Optional deps not installed | Medium | Use try/except ImportError and pytest.skip() |
| PyQt6 not available in CI | Medium | Guard Qt-dependent subpackage imports |
| Marker not registered | Low | Already registered in pyproject.toml |

## Rollback Boundaries

Single new file. If QA fails, delete file. No changes to existing code.
