# Execution Plan — Story E01S01

## Objective

Integrate the existing optimizer controls and reusable visualization components into a
force-source comparison lab with selectable pose, 30 N m wrist bounds, study import,
synchronized animations, and aligned speed/torque plots.

## Steps

1. Add failing tests for artifact validation, pose/settings propagation, objective
   selection, synchronized playback, and speed/torque series rendering.
2. Define a versioned comparison-artifact contract and strict runtime validation.
3. Extend the optimizer settings contract with objective, wrist bound, and search
   thoroughness while retaining the visible initial state.
4. Enforce a golf-like, non-looping, near-horizontal first-pass impact event in the
   browser optimizer and registered artifact interpretation.
5. Build comparison state and playback controls around the existing pendulum canvas and
   analysis plotting infrastructure.
6. Wire the optimizer panel into the application and add import/export affordances,
   provenance, robustness, and model-caveat presentation.
7. Verify responsive and accessible states, including errors, empty data, and running
   optimization.
8. Run unit/integration tests, TypeScript checks, the production build, and a live local
   browser journey with screenshot and console evidence.
9. Create a PR targeting `staging`.
10. Run `ci-watch-and-fix`; if CI passes, mark done; if CI still fails after the governed
    retry budget, mark failed.

## Dependencies

- UpstreamDrift comparison artifact schema version 1.

## Risks / Constraints

- Long optimization work must not freeze playback or make progress appear complete.
- Study artifacts are external input and require strict validation.
- Existing plotting and canvas components should be extended rather than duplicated.
