# GH1478 Execution Plan: Adversarial Assessment — src/pendulum_simulator

## Assessment Summary

The adversarial assessment flagged DbC and LoD violations in `src/pendulum_simulator`. After reviewing the actual code:

- **LoD violations**: Legitimate chained attribute access patterns exist in conftest.py (pathlib chain), signal_test.py (Qt pattern), and docs/conf.py (os.path chain). These are standard Python idioms for configuration/setup files, but the LoD rule applies uniformly.
- **DbC violations**: Functions in `physics_native.py` have only partial preconditions (validate first argument only). `club_forces.py` and `constraint_solver.py` functions have `assert x is not None` guards only — no type or range validation.

## Files to Modify

| File | Violation Type | Action |
|------|---------------|--------|
| `src/pendulum_simulator/conftest.py` | LoD — `Path(__file__).resolve().parent` (3-chain) | Extract intermediate to local var |
| `src/pendulum_simulator/signal_test.py` | LoD — `button.clicked.connect(self.run_requested.emit)` (2-chain ok; but `.run_requested.emit` is 2-chain passed as arg) | Minimal: extract `self.run_requested.emit` to local or suppress — this is idiomatic Qt |
| `src/pendulum_simulator/docs/conf.py` | LoD — `os.path.abspath(...)` is 2-level, `sys.path.insert` is 2-level | These are not LoD violations (2-level is compliant); no change needed |
| `src/pendulum_simulator/pendulum-core/python/physics_native.py` | DbC — `DoublePendulumParams.__init__` validates m1 only; `GolferParams.__init__` validates l_hub only | Add proper type+range validation for all constructor params |
| `src/pendulum_simulator/src/double_pendulum_golf/club_forces.py` | DbC — `overall_club_decomposition`, `ztcf_club_decomposition`, `delta_club_decomposition` have minimal guards | Add type and shape validation |
| `src/pendulum_simulator/src/double_pendulum_golf/constraint_solver.py` | DbC — `constrained_accelerations`, `constraint_forces` have minimal guards | Add type and shape validation |

## Implementation Steps

### Step 1: Fix conftest.py LoD violation
Extract `pathlib.Path(__file__).resolve().parent` chain by using an intermediate variable.

### Step 2: Fix signal_test.py LoD
`button.clicked.connect(self.run_requested.emit)` — `.clicked.connect` is 2-level and `.run_requested.emit` is a 2-level attribute reference used as a callable argument. This is standard Qt idiom. The LoD rule (`No method chains >2 levels`) is not violated. No change needed.

### Step 3: docs/conf.py
`os.path.abspath(...)` is a 2-level access, within policy. `sys.path.insert(...)` is also 2-level. No LoD violation. No change needed.

### Step 4: physics_native.py — Add proper DbC validation
`DoublePendulumParams.__init__`: Add `isinstance` type checks and range assertions for all physics parameters (masses > 0, lengths > 0, g > 0).
`GolferParams.__init__`: Same pattern for all params.
`DoublePendulum.__init__` and `Golfer.__init__`: Validate all constructor args.

### Step 5: club_forces.py — Strengthen DbC
`overall_club_decomposition`, `ztcf_club_decomposition`, `delta_club_decomposition`: Add `isinstance(state, np.ndarray)` and `state.ndim == 1` type/shape validation.

### Step 6: constraint_solver.py — Strengthen DbC
`constrained_accelerations`, `constraint_forces`: Add numpy array type + shape validation.

### Step 7: Add/update tests
AC2 requires all new code has tests. Since the changes are adding input validation, add unit tests covering:
- Invalid input (wrong type, wrong range) triggers the expected exception
- Valid input still works

## Edge Cases

- physics_native.py parameters like `g=9.81` are default — need to validate only when user provides them
- `friction1`, `friction2` can be 0.0 (not strictly > 0)
- `m_clubhead` can be 0.0 (optional point mass at tip)
- signal_test.py is not in src/ — print() rules don't apply to it
- docs/conf.py is Sphinx configuration — not production code

## Risk Register

- No public API changes — existing callers with valid inputs unaffected
- Rollback: revert to assert-only pattern
