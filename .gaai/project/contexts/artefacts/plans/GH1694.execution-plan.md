# Execution Plan — GH1694

## Story Summary

Replace `xml.etree.ElementTree` stdlib usage with `defusedxml.ElementTree` equivalents in 6
production files to eliminate XXE vulnerability exposure.

## Findings After Code Review

After reviewing all 6 files cited in the story:

| File | Actual Issue | Action |
|------|-------------|--------|
| `urdf_generator.py` | Uses ET only for *writing* (ET.Element, SubElement, tostring) + defusedxml.minidom for pretty-print. No untrusted input parsed. | Remove unused stdlib ET import for writing, keep ET for construction. Actually ET is needed for write path — no change needed. |
| `text_editor.py` | Parses exclusively via DefusedET. ET used for ParseError type + ET.tostring(). | ET.tostring is write-only. stdlib ET needed for output path. No parsing vulnerability. |
| `urdf_parser.py` | Parses via DefusedET.fromstring(). ET used for ParseError + type hints. | Already secure. |
| `format_utils.py` | Parses via DefusedET.fromstring(). StdET used only for ParseError exception. | Replace StdET.ParseError with DefusedET.ParseError (it re-exports from stdlib). |
| `mjcf_converter.py` | Parses via DefusedET.fromstring(). ET used for type hints (ET.Element) and NOT for parsing. | Move stdlib ET import to TYPE_CHECKING guard. |
| `mdl_parser.py` | Parses via DefusedET.parse() and DefusedET.fromstring(). ET used for ParseError + type hints. | Move stdlib ET import to TYPE_CHECKING guard; use defusedxml.ElementTree.ParseError at runtime. |

## Approach

**Files 1-3 (`urdf_generator.py`, `text_editor.py`, `urdf_parser.py`):** These already use defusedxml for
all XML parsing. The stdlib ET import is needed for the write/output path or only for type hints in a
way that is already safe. No security-impacting change needed. However, for defense-in-depth and
to satisfy the AC (the issue is about the import pattern), we will guard the stdlib ET import under
`TYPE_CHECKING` where it is only used for type annotations.

**Files 4-6 (`format_utils.py`, `mjcf_converter.py`, `mdl_parser.py`):**
- Remove runtime `import xml.etree.ElementTree as ET`
- Use `defusedxml.ElementTree.ParseError` (confirmed available) for exception handling
- Guard any remaining `ET.Element` usage under `TYPE_CHECKING`

**For files where ET is used in write path** (`urdf_generator.py`, `text_editor.py`):
ET.Element/SubElement/tostring are *write* operations building output from trusted internal data.
These are not vulnerable to XXE. We document this with a comment but do not change behavior.

## Test Strategy

- Unit tests verifying defusedxml rejects XXE payloads where parsing occurs
- Tests for files that already had tests (format_utils, text_editor)
- New tests for mjcf_converter and mdl_parser XXE rejection

3. AC3: ruff check passes
