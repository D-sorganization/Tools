# GH1649 Execution Plan — Refactor Oversized Files

## Story Summary

Split two files exceeding the 1200-line budget:
- `src/rotation_converter/modern_robotics.py` (2079L) → 3 submodules
- `src/shared/python/upstream_drift_tools/process_calculators/pressure_drop_calculator/pressure_drop_interface.py` (1390L) → 4 submodules

## Approach

**Structural refactor with backward-compatible re-exports.** The public API contract (what callers import) must not change. The strategy:
1. Extract logical groups into private submodule files (prefix `_`)
2. The original file becomes a thin re-export shim (or retains the core calculation logic)
3. Existing tests continue to pass without modification
4. Contract tests must pass

## Implementation Sequence

### Phase 1: Split modern_robotics.py

**Target submodules:**

| File | Contents | Approx lines |
|------|----------|------|
| `_mr_rotation_matrices.py` | Internal helper `_near_zero`, SO(3) helpers (VecToso3, so3ToVec, MatrixExp3, MatrixLog3), SE(3) helpers (VecTose3, se3ToVec, TransToRp, RpToTrans, TransInv, _Adjoint, MatrixExp6, MatrixLog6), plus legacy projection/distance functions (Normalize, RotInv, AxisAng3, Adjoint, ScrewToAxis, AxisAng6, ProjectToSO3, ProjectToSE3, DistanceToSO3, DistanceToSE3, TestIfSO3, TestIfSE3) | ~620L |
| `_mr_kinematics.py` | FK (FKinSpace, FKinBody), Jacobians (JacobianSpace, JacobianBody), IK (IKinBody, IKinSpace), Trajectory (ScrewTrajectory, CubicTimeScaling, QuinticTimeScaling, JointTrajectory, CartesianTrajectory) | ~570L |
| `_mr_dynamics.py` | Dynamics: ad, InverseDynamics, MassMatrix, VelQuadraticForces, GravityForces, EndEffectorForces, ForwardDynamics, EulerStep, InverseDynamicsTrajectory, ForwardDynamicsTrajectory, ComputedTorque, SimulateControl | ~890L |
| `modern_robotics.py` (shim) | Imports everything from the 3 submodules, re-exports with `__all__` | ~80L |

**Import dependency order:**
- `_mr_rotation_matrices.py` has no intra-package deps (only numpy, math, _contracts)
- `_mr_kinematics.py` imports from `_mr_rotation_matrices`
- `_mr_dynamics.py` imports from `_mr_rotation_matrices` and `_mr_kinematics`
- `modern_robotics.py` imports from all three

## Edge Cases

- `_Adjoint` is private in modern_robotics.py — should stay private in `_mr_rotation_matrices.py`, exposed through `modern_robotics.py` only as `Adjoint` (public)
- `_mr_dynamics.py` uses `Adjoint` (public) not `_Adjoint` — must import correctly
- The `SimulateControl` function has import of `matplotlib` inline — keep this pattern
- pressure_drop_interface.py imports from `.engine`, `.models`, `.utils` — these relative imports must be correct in submodules too

## Risk Register

| Risk | Mitigation |
|------|-----------|
| Circular imports between submodules | Import order: rotation_matrices → kinematics → dynamics (no cycles) |
| `_near_zero` used by multiple submodules | Define in `_mr_rotation_matrices.py`, import in kinematics/dynamics |
| `_Adjoint` vs `Adjoint` confusion | `_Adjoint` stays private in rotation_matrices; `Adjoint` re-exported from modern_robotics shim |
| Relative import breakage in pressure_drop subfiles | All files are in the same package directory, relative imports stay `.engine`, `.models`, `.utils` |
| Tests importing from modern_robotics directly | Shim ensures all existing imports work unchanged |

## Rollback Boundaries

- Each file edit is atomic and reversible
- Original files are only modified at the end (after submodules are verified)
- If any checkpoint fails, revert the changed file only
