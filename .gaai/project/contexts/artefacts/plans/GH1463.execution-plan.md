**main_window.py** — DbC violation: `__init__` and `closeEvent` lack comprehensive preconditions. LoD violation:
- Line 167: `Qt.ContextMenuPolicy.CustomContextMenu` (3-level chain)
- Line 169: `self.customContextMenuRequested.connect(...)` (Qt signal — idiomatic)

### Assessment

Qt signal `.connect()` calls (`widget.signal.connect(cb)`) are inherent PyQt6 idiom and cannot be restructured without breaking Qt functionality. These are not genuine LoD violations that can be addressed.

Nested enum accesses (`Class.EnumClass.Value`) can be fixed by importing the enum class directly at the module level.

DbC violations in main_window.py `closeEvent`: the `event` argument is `QCloseEvent | None` — can add type check. `__init__` already has `assert calculator_name is not None`.

## Implementation Steps

### Step 1: Fix LoD violations in widget_factory.py

Add direct imports for enum classes used in nested access:
- Import `QAbstractSpinBox.ButtonSymbols` as `NoButtons` constant
- Import `QSlider.TickPosition` as `TicksBelow` constant

Approach: Add module-level constant aliases for the enum values to reduce chain depth.

### Step 2: Fix LoD violations in main_window.py

Add direct import for `Qt.ContextMenuPolicy.CustomContextMenu`:
- Create a module-level alias `_CUSTOM_CONTEXT_MENU = Qt.ContextMenuPolicy.CustomContextMenu`
- Use the alias in `__init__`

### Step 3: Fix remaining DbC violations in main_window.py

`closeEvent` — the `event` parameter is typed `QCloseEvent | None` but no precondition check. Add type validation.

### Step 4: Ensure tests cover changes

Review existing tests in `test_electrode_advisor_gui.py` and `test_electrode_advisor_contracts.py`. Add tests for DbC validation (passing wrong types) if not already present.
