# GH1491 Execution Plan: Address TDD, DRY, DbC, and LOD in src/tools

## Summary

The story reports DbC and LoD violations in four files in `src/tools/`. Static analysis of the
current codebase shows that most violations were already addressed in prior work. Three DbC
violations remain:

1. `icon_utils.py:convert_image_mode` — no precondition on `img` argument
2. `launch_utils.py:_stream_reader` — no precondition on `stream`, `prefix`, or `log_func`
3. `matlab_quality_utils.py:_run_matlab_script` — no precondition on `script_path`

The LoD violations described in the issue at `launch_utils.py` lines 242 and 293 are **not
present** in the current code — those lines contain valid single-level attribute access.

## Implementation Sequence

### Step 1 — Fix `icon_utils.py:convert_image_mode`
- Add `require(img is not None, "img must be provided")` as first statement
- Import of `require` already present at top of file

### Step 2 — Fix `launch_utils.py:_stream_reader`
- Add `require` preconditions for `stream`, `prefix`, and `log_func`
- `require` from `src.shared.python.contracts` is already imported

### Step 3 — Fix `matlab_quality_utils.py:_run_matlab_script`
- Add `require(isinstance(script_path, Path), "script_path must be a Path")`
- `require` is already imported

### Step 4 — Add/extend tests
- Extend `tests/tools/test_icon_utils.py` for `convert_image_mode` DbC
- Extend `tests/tools/test_launch_utils.py` for `_stream_reader` DbC
- `tests/tools/test_matlab_quality_utils.py` already has coverage for `_run_matlab_script`
  via integration paths; add a targeted DbC test

### Step 5 — Verify
- `ruff check` on modified files
- `ruff format --check` on modified files
- `pytest tests/tools/` — all must pass

## Edge Cases
- `convert_image_mode(None)` must raise `PreconditionError`
- `_stream_reader` with non-callable `log_func` must raise `PreconditionError`
- `_run_matlab_script` with non-Path must raise `PreconditionError`

## Risk Register
- LOW: All changes are additive (adding preconditions); no logic changes
- No API surface changes (all three functions are module-private or internal helpers)

## Rollback Boundaries
- Each file change is independent; any can be reverted without affecting others
