# GH1488 Execution Plan

## Story Summary

Address DbC and LoD violations in `src/steam_engine_calculator/python/steam_engine_calculator/ui/pyqt6/main_window.py`.

## Tier

Tier 2 — Core Team (1 source file, 1 test file, 5 acceptance criteria)

## Violation Analysis

### DbC Violations

All functions have `assert` guards which are disabled in optimized mode (`python -O`). Per DbC policy, preconditions must use explicit `raise` statements.

| Function | Current | Fix |
|----------|---------|-----|
| `format_temperature(value, unit)` | `assert value is not None` | Replace with `if value is None: raise TypeError(...)` |
| `format_pressure(value, unit)` | `assert value is not None` | Replace with `if value is None: raise TypeError(...)` |
| `_create_group(self, title)` | `assert title is not None` | Replace with `if not isinstance(title, str): raise TypeError(...)` |
| `_create_label(self, text)` | `assert text is not None` | Replace with `if not isinstance(text, str): raise TypeError(...)` |
| `_create_result_card(self, name, key, color)` | `assert name is not None` | Replace with `if not isinstance(name, str): raise TypeError(...)` + add `key` and `color` checks |
| `_display_results(self, result)` | `assert result is not None` | Replace with `if result is None: raise ValueError(...)` |

### LoD Violations

All violations are 3-level Qt enum chains. Fix: module-level aliases defined after imports.

| Alias | Chain |
|-------|-------|
| `_SCROLL_BAR_AS_NEEDED` | `Qt.ScrollBarPolicy.ScrollBarAsNeeded` |
| `_FONT_WEIGHT_BOLD` | `QFont.Weight.Bold` |
| `_ALIGN_CENTER` | `Qt.AlignmentFlag.AlignCenter` |
| `_FRAME_STYLED_PANEL` | `QFrame.Shape.StyledPanel` |

Lines to update: 169, 178, 270, 286, 295, 296, 300, 375, 389, 400.

## Edge Cases

- Qt enum aliases require PyQt6 at import time. Test file already mocks PyQt6.
- `format_temperature` and `format_pressure` are module-level functions (not methods), so they can be tested without instantiating the window.
- `_create_group`, `_create_label`, `_create_result_card`, `_display_results` are instance methods — test via mock Qt or by directly calling the validation logic.
- The `_create_result_card` also needs `key` and `color` type checks since all three args are `str`.

## Test Checkpoints

1. All existing tests pass (no regressions)
2. New DbC tests: TypeError/ValueError raised for invalid inputs
3. New LoD tests: module-level aliases have correct types
4. `ruff check` zero violations
5. `ruff format --check` zero diffs
