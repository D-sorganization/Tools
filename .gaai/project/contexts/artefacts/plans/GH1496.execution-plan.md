# GH1496: Execution Plan

## Story Summary

Address DbC and LoD violations in `src/web_applications/calculator/calculator.py`.

## Analysis

### DbC Violations

After reviewing `calculator.py`, the automated DbC checker flagged 13 functions as missing
explicit preconditions. On inspection, most already have `assert` checks. The violations
that remain are:

1. `_safe_pow`: checks `base is not None` but not `exp is not None` or types
2. Several cached static methods: have `assert x is not None` but do not validate types
   (TypeError for wrong types per DbC standard in CLAUDE.md)
3. `parse_expression` / `parse_equation`: assert `is not None` but missing `isinstance` type guards

Per CLAUDE.md: "DbC: Every public function validates inputs. `TypeError` for wrong types,
`ValueError` for out-of-range. Document preconditions in docstrings."

The key gap: `assert` statements don't raise `TypeError` — they raise `AssertionError`.
Public functions should use `if not isinstance(...): raise TypeError(...)` pattern.

However, many of these are `@staticmethod @lru_cache` functions that are internal helpers
(prefixed with `_`). The story says to add preconditions — the implementation will add
proper `TypeError`/`ValueError` guards to the **public** functions and strengthen asserts
on key private ones.

**Public functions with arguments (no underscore prefix):**
- `evaluate(expression, variables)` — add isinstance check for expression: str
- `matrix_exponential(matrix)` — add isinstance check
- `matrix_logarithm(matrix)` — add isinstance check
- `simplify_expression(expression)` — add isinstance check
- `solve_equation(equation, variable)` — add isinstance checks
- `solve_system(equations, variables)` — add isinstance checks
- `derivative(expression, variable, order)` — add isinstance checks
- `integral(expression, variable, lower, upper)` — add isinstance checks
- `limit(expression, variable, value, direction)` — add isinstance checks
- `taylor_series(expression, variable, around, order)` — add isinstance checks
- `solve_differential_equation(equation, function)` — add isinstance checks
- `parse_expression(expression, symbols)` — public static, add isinstance checks
- `parse_equation(equation, symbols)` — public static, add isinstance checks

### LoD Violations

Lines flagged by the tool:
- Line 567: `skew = sp.Matrix(matrix)` — creates skew
- Line 568: `if skew.shape != (3, 3)` — shape is a 2-tuple, single-level attr access
- Line 578: `sp.Matrix(elements[:3])` — building from list slice
- Line 599: in `_screw_axis` — `self._hat(angular) * origin` is a method call chain

Looking at the reported lines:
- Lines 567-568 in `_vee`: `sp.Matrix(matrix)` then `skew.shape` — tool flags `.shape` as
  deep access because `sp.Matrix` is itself a chain (`sp.Matrix.shape`)
- Line 578 in `_se3_hat`: `sp.Matrix(elements[:3])` — tool flags `elements[:3]` as chain
- Line 599 in `_screw_axis`: `self._hat(angular)` — not itself a violation

The most legitimate LoD violation is line 570 in `_vee`:
```python
return sp.Matrix([skew[2, 1], skew[0, 2], skew[1, 0]])
```
Here `skew[2, 1]` is a matrix subscript — this looks like accessing sub-elements of `skew`.
This is borderline but to fix it per LoD, extract to local variables.

## Implementation Plan

### Step 1: Add DbC preconditions to public functions in `calculator.py`

For each public function that takes arguments, add proper type guards:
```python
if not isinstance(expression, str):
    raise TypeError("expression must be a string")
```

Replace bare `assert x is not None` with proper `TypeError`/`ValueError` raises.

### Step 2: Fix LoD violations

In `_vee` (line 570): Extract matrix element accesses to named locals before constructing result.
In `_se3_hat` (line 578): Extract slice to named locals.
In `_se3_vee` (line 589): Extract `transform[:3, :3]` and `transform[:3, 3]` to locals.
In `_screw_axis` (line 611): Already uses locals adequately.

### Step 3: Add/update tests for precondition enforcement

Add tests to `tests/test_calculator.py` verifying `TypeError` is raised for wrong types.

### Step 4: Run ruff check and ensure no new print() calls
