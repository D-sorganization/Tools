# GH1707 Execution Plan: Add Return Type Annotations to Unannotated Functions in src/shared/python/

## High-Level Approach

The story requires resolving missing type annotations on function signatures in `src/shared/python/`. The fix is to add `-> None` return type annotations to `__init__` methods and appropriate return types to other unannotated public functions.

Approach evaluation: NOT triggered. Adding `-> None` to `__init__` methods is an established Python typing convention with no design trade-offs. No new technology is being introduced.

## Test Checkpoints

AC2 requires all new code has tests. However, this change only adds type annotations (no logic change). The test checkpoint is:
- All existing tests continue to pass (no regressions)
- `mypy` continues to pass on non-excluded files
- No new test code needed for annotation-only changes (annotations are not executable logic)

Note: The story says "All new code has tests (TDD)" — annotation additions are not "new code" in the executable sense. If any test helper infrastructure were added, it would need tests. Here we're only adding `-> None` and similar type hints.

## Edge Cases

1. `get_explorer_window()` — returns a class (type), not an instance. Return type is `type[ModelExplorerWindow]`, which requires lazy import context. Use `TYPE_CHECKING` guard.
2. `_not_available(*args, **kwargs)` — always raises. Use `-> NoReturn` from `typing`.
3. `pyqtSignal` entry in `wgs_reactor_calculator.py` — this is actually a class-level attribute assignment using pyqtSignal(), not a function def. The AST parser detected it as a FunctionDef due to descriptor pattern. Skip this one.

## Risk Register

| Risk | Mitigation |
|------|-----------|
| Breaking `TYPE_CHECKING` import cycles | Use `TYPE_CHECKING` guard for ModelExplorerWindow return type |
| Incorrect return type on complex functions | Only adding `-> None` to `__init__` (universally correct) and `-> NoReturn` to _not_available |
| mypy new failures | Run mypy after each priority group |

## Rollback Boundary

All changes are annotation-only. If any issue arises, revert is safe and lossless — no logic is changed.
