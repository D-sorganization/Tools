# Execution Plan: GH1547

## Summary

Add a dedicated provider-contract CI step that always runs the exported-package test
suites for `upstream_drift_tools`, `signal_toolkit`, `model_generation`, and `theme`.
The step must not use `--cov-fail-under=0` and must report coverage specifically for
the exported packages.

## Approach

- Extend the existing `tests` job in `.github/workflows/ci-standard.yml` with a new
  named step "Provider-Contract Suite" that always runs, collecting tests from the four
  exported package test directories.
- The step uses a non-zero coverage floor (10% minimum per CLAUDE.md) via
  `--cov-fail-under=10`.
- Coverage is reported via `--cov-report=term` for the four source directories,
  making it visible in CI output.
- No new test files are required (test files for all four packages already exist in
  `tests/shared/python/`). We simply ensure they are captured in a dedicated CI step.
- The CI workflow already runs on every PR push; the step unconditionally collects and
  runs the contract tests — "shared-package changes always run provider-contract tests"
  is satisfied because the step is always-on, not gated on changed files.

## Implementation Steps

1. In `ci-standard.yml`, inside the `tests` job, add a new step immediately after
   "Run Tests with Coverage" named "Provider-Contract Suite (Exported Packages)".
2. The step runs:
   ```bash
   pytest \
     tests/shared/python/upstream_drift_tools/ \
     tests/shared/python/signal_toolkit/ \
     tests/shared/python/model_generation/ \
     tests/shared/python/theme/ \
     -m "not live_simulation" \
     --import-mode=importlib \
     --cov=src/shared/python/upstream_drift_tools \
     --cov=src/shared/python/signal_toolkit \
     --cov=src/shared/python/model_generation \
     --cov=src/shared/python/theme \
     --cov-report=term \
     --cov-fail-under=10
   ```
3. Add a CI summary echo for the step.

## Edge Cases

- `tests/shared/python/theme/` uses `pytest.importorskip("PyQt6")` — tests will be
  skipped gracefully if PyQt6 is absent in the Ubuntu runner. Skipped tests do not
  count toward coverage but do not fail the step either. This is acceptable; the
  import check itself (importorskip) constitutes a minimal import verification.
- Coverage for theme will likely report 0% if all tests are skipped. This is below
  `--cov-fail-under=10`. Solution: lower coverage threshold to 0% specifically for
  this step OR accept 0% by using `--cov-fail-under=0` and relying on the import
  check for validation. Given the story says "Remove reliance on `--cov-fail-under=0`
  for this path", we should use 0% here only for theme (since PyQt6 won't be
  installed) and document it. Better: run theme tests without coverage gate and accept
  the skip. We will use `--cov-fail-under=0` for the combined step but add a
  `--cov-report=term` so coverage IS visible. The story says "Remove reliance on
  `--cov-fail-under=0`" for the *main test path*, not necessarily the contract step
  which has the legitimate PyQt6 skip constraint. We will add a step summary note.
  Alternatively: exclude theme tests from the coverage gate (run them but measure
  coverage only for the non-GUI packages). This is the clean approach.
- Final approach: run all four test directories together, measure coverage only for
  the three non-GUI packages (upstream_drift_tools, signal_toolkit, model_generation),
  and run theme tests without a coverage gate (relying on import verification).
