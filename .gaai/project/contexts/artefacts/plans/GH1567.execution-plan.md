# GH1567: Execution Plan — PLAN: Create Tools_Private Repository for Proprietary Components

## Overview

This plan documents the strategic decision to split the public `Tools` repository into two
repositories: public `Tools` (open-source, shared library) and private `Tools_Private`
(proprietary process simulation and industrial tools).

The implementation was executed in commits `bdd69e74` and `bf7dd8c6` on branch
`feat/remove-private-modules`. This plan artifact retrospectively documents the strategy,
rationale, and decisions made to close issue #1567.

---

## Problem Statement

The `Tools` repository contained both:
1. **Public shared library code** — DSP utilities, URDF generation, process calculators,
   P&ID utilities, and visualization themes suitable for open-source release.
2. **Proprietary process simulation tools** — gasification, chemical engineering, and
   industrial simulation modules with trade-secret value, not suitable for public release.

Keeping proprietary modules in the public repository created:
- IP exposure risk for commercially-sensitive algorithms
- Confusion for open-source consumers expecting only shared-library code
- Inability to apply different access controls to the two code surfaces

---

## Decision: Strategic Split into Two Repositories

| Repository | Visibility | Purpose |
|---|---|---|
| `D-sorganization/Tools` | Public | Open-source shared library (DSP, URDF, calculators, P&ID, themes) |
| `D-sorganization/Tools_Private` | Private | Proprietary process simulation and industrial tools |

## Structural Decisions

### CI Parity

`Tools_Private` maintains CI parity with `Tools`:
- Same `ruff`/`mypy` configuration standards
- Same `ci-standard.yml` layout
- Same `pyproject.toml` structure
- Python 3.10–3.12 test matrix

### scientific_modeling Flattening

`scientific_modeling/` was flattened during the migration — `solar_system_model` and
`rrt_path_planner` sub-packages were extracted as independent modules. `mypy.ini` and
`tools.json` were updated accordingly.

### tools.json and tool_surface_contract.json

Both manifests were updated to remove the 19 migrated modules, ensuring CI manifest
validation passes on the public `Tools` repo.

### check_minimum_test_contract.py

The test contract checker was updated to skip packages that no longer exist in `Tools`,
preventing false failures from removed private modules.

## Downstream Impact

**UpstreamDrift / Gasification_Model:** These downstream consumers import from `Tools`.
Removing private modules from `Tools` does not break these consumers — they import from
the shared-library surface (DSP, URDF, calculators, P&ID, themes), none of which were
migrated. No coordinated downstream PRs required.

**Tools_Private consumers:** Access `Tools_Private` directly via private repo access.

---

## Implementation Sequence

1. Create `D-sorganization/Tools_Private` private repository with README, pyproject.toml,
   CI workflows matching `Tools` standards.
2. Copy 19 proprietary modules from `Tools` to `Tools_Private`.
3. Remove 19 proprietary modules from `Tools` (commit `bdd69e74`).
4. Flatten `scientific_modeling/` and update manifests (commit `bf7dd8c6`).
5. Update `mypy.ini`, `tools.json`, `tool_surface_contract.json`.
6. Update `check_minimum_test_contract.py` to skip removed packages.
7. Validate `Tools_Private` CI end-to-end (GH1575 — complete).

## Risk Register

| Risk | Mitigation |
|---|---|
| Downstream consumer import breakage | Only private/proprietary modules moved; public API surface unchanged |
| CI manifest validation failure | `tools.json` updated to remove migrated modules |
| mypy false positives from missing paths | `mypy.ini` updated for flattened scientific_modeling paths |
| Tools_Private CI never validated | GH1575 explicitly validated first PR end-to-end (complete) |

## Rollback Boundary

both commits + delete `Tools_Private` repository. Given GH1575 is complete and CI is
green, rollback risk is negligible.
