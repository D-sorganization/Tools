# GH1487 Execution Plan

## Objective

Address DbC and LoD violations in `src/signal_processing_studio` — two source files plus a test file.

## Approach

Follow the same DbC/LoD remediation pattern established in GH1489:
- Replace `assert` statements with explicit `raise ValueError`/`raise TypeError` guards
- Extract LoD-violating Qt signal connections into a helper method to eliminate 3-deep chains
- Add tests for all new preconditions

## Files to Modify

| File | Change |
|------|--------|
| `src/signal_processing_studio/python/signal_processing_studio/signal_bus.py` | DbC fixes: replace asserts with raise statements; add preconditions to `__init__` |
| `src/signal_processing_studio/python/signal_processing_studio/main_window.py` | DbC fix for `_on_poly_fallback`; LoD fix for lines 111, 117, 125 |
| `src/signal_processing_studio/tests/test_signal_processing_studio.py` | Add tests for all new preconditions |

## Step-by-Step Plan

### Step 1: Fix `signal_bus.py` DbC violations

1a. `__init__`: Add preconditions for `func_gen`, `toolkit`, `poly_gen` (not None)
1b. `_on_func_gen_signal`: Replace `assert signal is not None` with `if signal is None: raise ValueError("signal must not be None")`
1c. `_on_poly_generated`: Replace `assert joint_name is not None` with proper ValueError + add `coeffs` type check
1d. `_status`: Replace `assert message is not None` with `if message is None: raise ValueError("message must not be None")`

### Step 2: Fix `main_window.py` violations

2a. DbC fix for `_on_poly_fallback`:
   - Replace `assert joint_name is not None` with `raise ValueError`
   - Add `coeffs` validation: not None, must be a list

2b. LoD fix for lines 111, 117, 125 (Qt `.triggered.connect()` chains):
   - Add a module-level helper `_connect_action(action, slot)` that wraps the 2-dot chain
   - Use `_connect_action(send_action, self._send_to_toolkit)` etc.

### Step 3: Add tests

3a. Tests for `signal_bus.py`:
   - `test_init_raises_for_none_func_gen`
   - `test_init_raises_for_none_toolkit`
   - `test_init_raises_for_none_poly_gen`
   - `test_on_func_gen_signal_raises_for_none_signal`
   - `test_on_poly_generated_raises_for_none_joint_name`
   - `test_on_poly_generated_raises_for_invalid_coeffs`
   - `test_status_raises_for_none_message`

3b. Tests for `main_window.py`:
   - `test_on_poly_fallback_raises_for_none_joint_name`
   - `test_on_poly_fallback_raises_type_error_for_non_list_coeffs`
   - `test_connect_action_helper_exists` (module-level helper)

## Edge Cases

- `status_callback=None` in `__init__` is valid (optional) — do not raise for None callback
- `coeffs=[]` (empty list) is valid — only validate it's a list, not length
- LoD fix should use helper to avoid 3-deep Qt chains

## Test Checkpoints

1. Run `ruff check` on modified files — must be zero violations
2. Run `ruff format --check` on modified files — must be zero diffs
3. Run existing tests for signal_processing_studio — must not regress
4. New DbC tests all pass

## Risk Register

- LOW: Qt signal `.triggered.connect()` is idiomatic; extracting to helper may surprise Qt developers but is within scope
- LOW: Tests for `__init__` DbC require bypassing Qt object init — use `SignalBus.__new__` pattern already established in test file

## Rollback Boundary

All changes are in `src/signal_processing_studio/` — no changes to public API signatures.
