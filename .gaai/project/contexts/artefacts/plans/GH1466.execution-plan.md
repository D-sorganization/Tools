# GH1466 Execution Plan — LoD Violations in src/flow_rate_converter

## Summary

Fix 10 Law of Demeter violations in `main_window.py` by extracting module-level or
local constants for repeated multi-level Qt enum attribute chains. All violations are
of the same two patterns: `Qt.AlignmentFlag.AlignCenter` and `QSizePolicy.Policy.*`.
Add tests covering the LoD-fixed code structure. Ensure `ruff check` passes.

## Implementation Sequence

### Step 1: Add module-level constants for repeated Qt enum chains

**File:** `src/flow_rate_converter/python/flow_rate_converter/ui/pyqt6/main_window.py`

After the imports section, add module-level constants:

```python
# LoD: extract repeated Qt enum chains to named constants
_ALIGN_CENTER = Qt.AlignmentFlag.AlignCenter
_EXPANDING = QSizePolicy.Policy.Expanding
_FIXED = QSizePolicy.Policy.Fixed
```

### Step 2: Replace all 10 LoD violations with the named constants

Replace in each of the three `_create_*_tab` methods:
- Line 232 (mass tab): `Qt.AlignmentFlag.AlignCenter` → `_ALIGN_CENTER`
- Line 262 (mass tab): `QSizePolicy.Policy.Expanding` → `_EXPANDING`, `QSizePolicy.Policy.Fixed` → `_FIXED`
- Line 298 (mass tab): `Qt.AlignmentFlag.AlignCenter` → `_ALIGN_CENTER`
- Line 324 (molar tab): `QSizePolicy.Policy.Expanding` → `_EXPANDING`, `QSizePolicy.Policy.Fixed` → `_FIXED`
- Line 380 (molar tab): `Qt.AlignmentFlag.AlignCenter` → `_ALIGN_CENTER`
- Line 406 (vol tab): `QSizePolicy.Policy.Expanding` → `_EXPANDING`, `QSizePolicy.Policy.Fixed` → `_FIXED`
- Line 466 (vol tab): `Qt.AlignmentFlag.AlignCenter` → `_ALIGN_CENTER`

### Step 3: Run ruff check + format on the modified file

```bash
python3 -m ruff check src/flow_rate_converter/python/flow_rate_converter/ui/pyqt6/main_window.py
python3 -m ruff format src/flow_rate_converter/python/flow_rate_converter/ui/pyqt6/main_window.py
```

### Step 4: Add/extend tests for LoD-fixed constants

**File:** `src/flow_rate_converter/tests/test_flow_rate_converter_gui.py`

Add a new test class `TestFlowRateConverterLoDConstants` verifying:
- The three module-level constants are present and have correct values
- No deep attribute chain is called at import time (verified by mocking)

## Edge Cases

- Qt enum values must not be used before constants are defined (put constants after imports)
- Tests must use mocking for PyQt6 since headless env has no display
- `ruff` treats chained attribute access as style, not error — the LoD fix is a code quality change, not a lint fix

## Test Checkpoints

1. `ruff check` zero violations on modified file
2. `ruff format --check` zero diffs on modified file
3. New tests in `TestFlowRateConverterLoDConstants` pass
4. Existing tests still pass (no regression)
