# GH1587 Execution Plan: Add Tests for Key Untested Shared-Library Modules

## Summary

The issue reports 630 source modules with no matching `test_<module>.py` file. Audit reveals
the original count was based on an incomplete analysis (missing embedded test directories and
the `tests/` top-level directory). Actual untested modules in the shared library (the highest
priority target, as downstream repos depend on it) are approximately 200.

This plan delivers tests for the two highest-priority genuinely-untested calculator backend
modules in `src/shared/python/upstream_drift_tools/process_calculators/`:

1. `pressure_drop_calculation_engine.py` — pure functions for friction factor calculations,
   flow property computation, elevation/compressibility corrections, and the
   `PressureDropCalculationEngine` class. These are scientifically testable with no UI deps.
2. `water_vapor_pressure_calculator.py` — `WaterVaporPressureCalculator` wrapper class
   (the underlying `SyngasWaterCalculator` already has tests; this wrapper does not).

**Why these modules?**
- Explicitly mentioned in issue #1587 as key gaps ("multiple calculator backends")
- They are pure Python with no PyQt6/display dependencies (CI-runnable)
- They are part of the shared library consumed by UpstreamDrift and Gasification_Model
- The pressure drop engine is a 1100-line module with no test coverage at all

**Why not signal_toolkit or model_generation?**
- `signal_toolkit/polynomial_generator.py` — hard PyQt6 dependency, requires display server
- `signal_toolkit/widget*.py` — all PyQt6 UI code, requires Qt test harness
- `model_generation` converters/builders — complex XML/file-system dependencies; better
  addressed as separate focused stories (GH1469-GH1498 adversarial assessment series)

## Implementation Sequence

### Step 1 — pressure_drop_calculation_engine tests (AC1, AC2)

Key test logic:
- Laminar: Re=1000 → f=0.064

## Edge Cases

- `PressureDropCalculationEngine.calculate()` requires `PressureDropInputs` with valid
  gas composition that sums to ~1.0. Use the syngas example from the module's `__main__` block.
- Colebrook iteration: for extreme conditions (very low Re, very high ε/D) the function
  falls back gracefully — do not test at numerical limits that cause divergence.
- `WaterVaporPressureCalculator.calculate_vapor_pressure()` uses assert-not-None guard
  on temperature_c — do not pass None.
