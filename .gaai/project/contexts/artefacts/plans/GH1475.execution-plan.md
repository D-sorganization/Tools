# GH1475 Execution Plan: Address TDD, DRY, DbC, and LOD in src/multi_param_analysis

## Story Summary

Fix DbC violations (3 functions missing proper preconditions) and LoD violations (7 deep Qt attribute
accesses) in `src/multi_param_analysis/python/multi_param_analysis/ui/pyqt6/main_window.py`.
Add tests covering the DbC enforcement.

## Tier

Tier 2 (complexity ~3, 1 source file + 1 test file, well-defined violations).

## Implementation Sequence

### Step 1: Fix LoD Violations — Extract Qt Constants

Extract 3 deep Qt attribute chains (>2 levels) to module-level aliases immediately after imports.

- `Qt.ScrollBarPolicy.ScrollBarAlwaysOff` → `_SCROLLBAR_ALWAYS_OFF`
- `Qt.AlignmentFlag.AlignCenter` → `_ALIGN_CENTER`
- `QSizePolicy.Policy.Expanding` → `_SIZE_EXPANDING`
- `QSizePolicy.Policy.Fixed` → `_SIZE_FIXED`

Replace all usages of these chains in `_setup_ui` and `_create_parameters_tab`.

### Step 2: Fix DbC Violations — Replace assert with proper raises

Three functions have `assert` statements which:
- Can be disabled with `-O` optimization flag
- Raise `AssertionError` instead of `TypeError`/`ValueError` per DbC rules

Replace:
- `_run_demo_analysis`: validate all 5 arguments
  - `param1_name`, `param2_name`, `output_name` → `TypeError` if not str
  - `param1_values`, `param2_values` → `TypeError` if not np.ndarray
- `_calculate_sensitivity`: validate all 3 arguments
  - `param1_values`, `param2_values` → `TypeError` if not np.ndarray
  - `Z` → `TypeError` if not np.ndarray
- `_update_preview`: validate all 3 arguments
  - `param1_values`, `param2_values` → `TypeError` if not np.ndarray
  - `Z` → `TypeError` if not np.ndarray

### Step 3: Add Tests for DbC Enforcement

In `src/multi_param_analysis/tests/test_multi_param_analysis_gui.py`, add a new test class
`TestDbCEnforcement` with tests that:
- Verify `_run_demo_analysis` raises `TypeError` for wrong types
- Verify `_calculate_sensitivity` raises `TypeError` for wrong types
- Verify `_update_preview` raises `TypeError` for wrong types

Tests must run headless (use pytest markers, avoid actual PyQt6 instantiation).

## Edge Cases

- Qt attribute chains appear in `__init__` scope via `_setup_ui` and `_create_parameters_tab`
- `QSizePolicy.Policy.Expanding/Fixed` appear in two different methods — both must be updated
- The `assert` in `_run_demo_analysis` also covers `param1_name is not None` — the replacement
  must be `isinstance` check (str), which implicitly also catches None
