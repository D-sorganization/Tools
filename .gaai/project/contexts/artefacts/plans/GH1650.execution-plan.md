# GH1650: Execution Plan — Enforce function length limit and refactor violations

## Story Summary

Refactor 3 specific functions that exceed the 50-line threshold:
- `InverseDynamics` in `modern_robotics.py` (86L)
- `calculate_pressure_drop` in `pressure_drop_interface.py` (100L)
- `_build_ui` in `rotation_converter/ui/pyqt6/main_window.py` (84L, `RotationConverterTab`)

## Complexity Assessment

**Tier 2** — 3 files, algorithmic refactoring, test requirements.

## Approach

### 1. `InverseDynamics` (modern_robotics.py)

The function has 52 lines of docstring/signature and 33 lines of actual logic.
The logic has two well-defined phases:
- **Forward pass** (lines 1039–1050): propagates velocities/accelerations forward through joints
- **Backward pass** (lines 1051–1059): propagates forces backward to compute torques

Refactor: extract `_inverse_dynamics_forward_pass` and `_inverse_dynamics_backward_pass`
as module-level private helpers. `InverseDynamics` becomes a thin orchestrator.
The public API signature is unchanged.

**Post-refactor line count:** ~35L (signature + docstring + 3 helper calls)

### 2. `calculate_pressure_drop` (pressure_drop_interface.py)

The function is 100L total but the body is only 35L. Length comes from:
- 25-parameter signature (~25L)
- Full docstring with Args/Returns/Example (~40L)

The body already delegates cleanly to `_resolve_pipe_geometry`, `_resolve_gas_and_flow`,
`_build_fitting_list`, `PressureDropInputs`, and `_format_results`.

**Strategy:** Extract parameter grouping into a `_PipeFlowParams` dataclass (or named tuple)
to compress the signature. However, this would change the public API and require downstream
coordination — **out of scope for this story**.

Alternative: Extract the docstring example into a module-level constant or accept that
long docstrings are not a code quality violation. The function body itself is clean.

**Decision:** Since the length is docstring + parameter list (not implementation complexity),
and changing the signature would be a breaking API change, we will refactor by extracting
the input validation and unit conversion into a `_resolve_inputs` helper, reducing the
body to ~20L. The public signature is unchanged.

### 3. `_build_ui` (rotation_converter/ui/pyqt6/main_window.py, RotationConverterTab)

The 84L `_build_ui` builds three logical sections:
- Input group (QGroupBox "Input Rotation"): ~18L
- Output section (target combo + all-representations text): ~20L
- Plot section (matplotlib figure + toolbar): ~15L
- Layout assembly: ~15L

Refactor: extract `_build_input_group() -> QGroupBox`, `_build_output_section() -> QVBoxLayout`,
`_build_plot_section() -> QGroupBox` as private instance methods.
`_build_ui` becomes ~20L assembly glue.

## Implementation Sequence

1. Refactor `InverseDynamics` in `modern_robotics.py`
   - Add `_inverse_dynamics_forward_pass` (private, module-level)
   - Add `_inverse_dynamics_backward_pass` (private, module-level)
   - Slim `InverseDynamics` body to call helpers

2. Refactor `calculate_pressure_drop` in `pressure_drop_interface.py`
   - Extract `_resolve_inputs` helper that handles temperature/pressure conversion
     and pipe geometry resolution
   - Reduces body by ~10L while keeping public API intact

3. Refactor `_build_ui` in `rotation_converter/ui/pyqt6/main_window.py`
   - Extract `_build_input_group`, `_build_output_section`, `_build_plot_section`
   - `_build_ui` becomes the layout assembler only

4. Add tests for the refactored functions
   - `tests/rotation_converter/test_modern_robotics.py` — `InverseDynamics` unit test
   - Existing `test_pressure_drop_interface.py` already covers `calculate_pressure_drop`; verify coverage

5. Run `ruff check` and `ruff format --check` on all modified files
