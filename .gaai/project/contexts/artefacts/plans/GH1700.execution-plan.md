# GH1700 Execution Plan — Standardize contracts module import paths

## Summary

Standardize all `from src.shared.python.contracts import` usages to `from contracts import`
(bare import), which resolves correctly because `src/shared/python` is on `pythonpath` in
`pytest.ini`. Remove the broken absolute-path style that would fail in packaged installs.

## Approach

Use `sed`-style replacement to change `from src.shared.python.contracts import` to
`from contracts import` across all affected files. The bare import is valid because:
- `src/shared/python` is listed in `pythonpath` in `pytest.ini`
- Tests already run with this pythonpath configuration (bare imports work today)
- All existing bare imports in the codebase prove the style works

For `data_processor/contracts.py`: change the `try:` block from
`from src.shared.python.contracts import` to `from contracts import` and remove the
`# type: ignore[import]` annotation (no longer needed since the bare import is clean).

For `contracts.py` docstring: update the `Usage` examples to show bare import style.

## Implementation Steps

1. Update `contracts.py` docstring examples
2. Update all src/ production imports (11 files)
3. Update all tests/ imports (10 files)
4. Run `ruff check` on all modified files
5. Run `ruff format --check` on all modified files
6. Run pytest on affected test files to verify nothing broken

## Edge Cases

- `config_loader.py` uses `from _bootstrap import bootstrap` and non-standard path setup.
  The inline `from src.shared.python.contracts import` inside functions will work as
  `from contracts import` since `src/shared/python` will be on sys.path when the module
  is loaded in context.
- `data_processor/contracts.py` has a `# type: ignore[import]` on the old import line.
  Remove it when changing to bare import.
- `contracts.py` docstring only — no functional code change needed there.
