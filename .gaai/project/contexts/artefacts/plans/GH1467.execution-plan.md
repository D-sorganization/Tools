# GH1467: Execution Plan — Adversarial Assessment: Address TDD, DRY, DbC, and LOD in src/folder_packer_pro

## Context

The `src/folder_packer_pro` module contains DbC and LoD violations identified in an adversarial
assessment. Most DbC violations have already been fixed (asserts are in place); the remaining
work is to fix the LoD violations in `file_ops.py` and write tests for the fixed functions.
The PR targets the `staging` branch of `D-sorganization/Tools`.

## Files Affected

| File | Issue |
|------|-------|
| `src/folder_packer_pro/file_ops.py` | LoD: `file_path.stat().st_size` (line 96) and `file_path.suffix.lower()` (lines 99, 116) |
| `tests/folder_packer_pro/test_file_ops.py` | NEW: tests for file_ops.py public functions (TDD requirement) |
| `tests/folder_packer_pro/__init__.py` | NEW: package init for test module |

## Current Violation Status

### Already Fixed (DbC)

All functions in `app.py`, `encryption.py`, `manifest.py`, `build_exe.py`, and `operations.py`
already have `assert` preconditions. No action needed.

### Remaining LoD Violations in file_ops.py

- Line 96: `size = file_path.stat().st_size` — method result chained to attribute
- Line 99: `ext = file_path.suffix.lower() or "no extension"` — property chained to method
- Line 116: `ext = file_path.suffix.lower()` — property chained to method

## Implementation Sequence

### Step 1: Fix LoD violations in file_ops.py

In `collect_folder_stats()`, extract the intermediate values:

```python
# Before
size = file_path.stat().st_size
ext = file_path.suffix.lower() or "no extension"

# After
stat_result = file_path.stat()
size = stat_result.st_size
raw_ext = file_path.suffix
ext = raw_ext.lower() or "no extension"
```

In `get_file_type()`:

```python
# Before
ext = file_path.suffix.lower()

# After
raw_suffix = file_path.suffix
ext = raw_suffix.lower()
```

### Step 2: Create test directory and write tests for file_ops.py

Create `tests/folder_packer_pro/__init__.py` (empty).

Create `tests/folder_packer_pro/test_file_ops.py` with tests for:
- `should_exclude()` — tests for path exclusion, git exclusion, pattern matching
- `collect_folder_stats()` — tests with temp directories
- `get_file_type()` — tests for all file type categories
- `format_size()` — tests for B, KB, MB, GB conversions

All tests marked `@pytest.mark.unit`.

### Step 3: Verify ruff and tests pass

Run `python3 -m ruff check src/folder_packer_pro/` — must show zero violations.
Run `python3 -m pytest tests/folder_packer_pro/ -v` — all tests must pass.

## Edge Cases

- `file_path.suffix.lower()` — suffix is a string property, splitting into two lines is safe
- `file_path.stat().st_size` — stat() can raise OSError which is already caught upstream
- Tests for `collect_folder_stats` use `tmp_path` pytest fixture (no side effects)
- `get_file_type` has no side effects, easy to unit test

## Test Checkpoints

1. All new tests pass: `pytest tests/folder_packer_pro/ -v`
2. Existing module tests unaffected
3. `ruff check src/folder_packer_pro/` — zero violations
4. No `print()` calls added

## Risk Register

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| `stat()` call in test requires real files | Low | Use `tmp_path` fixture for file creation |
| `collect_folder_stats` uses `os.walk` | Low | Create a real temp folder tree in tests |
| `format_size` floating point comparison | Low | Use `pytest.approx` or string assertions |

## Rollback Boundaries

- All changes are in `src/folder_packer_pro/file_ops.py` and `tests/folder_packer_pro/`
- No public API changes — `file_ops.py` function signatures unchanged
- No shared library or downstream contract impact

## Approach Rationale

Follows the established pattern from GH1472–GH1493: minimal, targeted LoD fixes by introducing
intermediate variables, plus unit tests for the affected public functions. No logic changes.
