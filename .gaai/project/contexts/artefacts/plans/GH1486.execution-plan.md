# GH1486 Execution Plan

## Story Summary

Fix TDD, DRY, DbC, and LoD violations in `src/shared` — specifically:
- DbC violations in contracts.py, cors.py, safe_eval.py, gui_launcher/registry.py
- LoD violations (deep attribute chains > 2 levels) in contracts.py (line 60), cors.py (line 64), safe_eval.py (lines 195–196)

## Root Cause Analysis

The test suite loads `src.shared.python.*` via the UpstreamDrift Python package
(installed on PYTHONPATH as `/home/dieterolson/Linux_Repositories/Linux_UpstreamDrift/UpstreamDrift`),
not from the local Tools `src/shared/python/` tree. UpstreamDrift's cors.py lacked
`require()` guards, and its registry.py had only bare `assert` statements rather
than proper `require()` DbC calls. Five tests were failing as a result.

The local Tools `src/shared/python/` files (cors.py had guards, registry.py had guards)
were correct but unused by the test runner.

## Approach

**Tier 2: Planning + Implementation + QA**

1. Add `require()` guards to UpstreamDrift `cors.py` (app type, origins type/content)
2. Replace `assert`-based guards in UpstreamDrift `gui_launcher/registry.py` with `require()` calls; add precondition to `auto_discover_guis`
3. Fix LoD violations in both UpstreamDrift and local Tools:
   - `contracts.py`: split `os.environ.get(...).lower().strip()` into two steps
   - `safe_eval.py`: extract `node.func.id` to local variable
4. Fix DbC asserts in UpstreamDrift `safe_eval.py` (replace duplicate asserts with `require()`)
