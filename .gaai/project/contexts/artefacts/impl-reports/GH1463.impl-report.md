# Implementation Report: GH1463 — Address TDD, DRY, DbC, and LOD in src/electrode_advisor

## Summary

Addressed all DbC and LoD violations in the `src/electrode_advisor` module (Tools_Private repo).
Replaced weak `assert x is not None` preconditions with proper `TypeError`/`ValueError` guards per codebase coding standards. Eliminated 3-level LoD attribute chains via module-level enum constant aliases. Added 20 new TDD tests covering all factory function preconditions.

## Changes by Acceptance Criterion

### AC1: Issue #1463 resolved

**DbC fixes (widget_factory.py):**
- `create_double_spinbox`: `assert min_value is not None` → `isinstance(min_value, (int, float))` TypeError + `min_value >= max_value` ValueError
- `create_slider`: `assert min_value is not None` → `isinstance(min_value, int)` TypeError + range ValueError
- `create_checkbox`: `assert text is not None` → `isinstance(text, str)` TypeError
- `create_readonly_lineedit`: `assert default_text is not None` → `isinstance(default_text, str)` TypeError
- `create_button`: `assert text is not None` → `isinstance(text, str)` TypeError
- `create_combobox`: `assert items is not None` → `isinstance(items, list)` TypeError + empty list ValueError
- `create_label`: `assert text is not None` → `isinstance(text, str)` TypeError

**DbC fixes (main_window.py):**
- `closeEvent`: Added `isinstance(event, QCloseEvent)` TypeError check

**LoD fixes (widget_factory.py):**
- `QAbstractSpinBox.ButtonSymbols.NoButtons` → `_NO_BUTTONS` (module-level alias)
- `QSlider.TickPosition.TicksBelow` → `_TICKS_BELOW` (module-level alias)

**LoD fixes (main_window.py):**
- `Qt.ContextMenuPolicy.CustomContextMenu` → `_CUSTOM_CONTEXT_MENU` (module-level alias)

**Qt signal chains (`.signal.connect(cb)`):** Left as-is — this is idiomatic PyQt6 API. Signal access is a single attribute, `.connect()` is a method call on that attribute. This is a 2-level chain that is the documented/required Qt pattern, not a genuine LoD violation.

## Known Limitations

- Qt signal `.connect()` chains (e.g., `widget.signal.connect(cb)`) are not addressed — these are inherent PyQt6 idiom, not genuine LoD violations
- `closeEvent` DbC check is a type guard only; Qt normally ensures the correct type
- `test_widget_factory_dbc.py` uses `importlib.util.spec_from_file_location` to load widget_factory directly (bypassing `electrode_advisor/__init__.py` which requires upstream_drift_tools at import time)
