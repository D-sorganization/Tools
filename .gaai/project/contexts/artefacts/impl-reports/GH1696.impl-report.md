## Key Decisions

1. **pressure_drop_calculator/_legacy.py**: The legacy `PressureDropCalculator` class contained an `assert` statement for precondition checking. This was upgraded to proper `TypeError`/`ValueError` raises per the DbC coding standards. The `if pipe_diameter_m > 0` guard was simplified since the new `ValueError` check already handles this.

2. **signal_toolkit lazy pattern**: Used the `_LAZY: dict[str, tuple[str, str]]` + `__getattr__` pattern (same as `data_processor/core/__init__.py` already used). The optional widget imports remain eager because: (a) PyQt6 IS available in this env and widget_processing imports all heavy submodules anyway, and (b) `HAS_WIDGET`/`HAS_POLYNOMIAL_GENERATOR` flags must be resolvable synchronously at import time.

3. **test design**: Subprocess-based tests for lazy loading would be complex in this environment (PyQt6 causes eager loading via widget_processing chain). Tests instead verify: (a) the `_LAZY` dict and `__getattr__` function exist (structural), (b) `__getattr__` correctly resolves and caches values, (c) `__all__` items are all accessible.

## Rules Applied

## Known Risks / Limitations

- `signal_toolkit` lazy imports in a PyQt6 environment have limited benefit because `widget_processing.py` imports all submodules transitively. The improvement is realized in headless/no-PyQt6 environments (CI, testing, CLI usage).
- The 5 other `__init__.py` files over 100 lines (`process_calculators`, `theme`, `rotation_converter`, `programmatic_pid`, `humanoid_character_builder`) were not addressed — they are less critical or already use optional patterns. A follow-up issue could address them.
