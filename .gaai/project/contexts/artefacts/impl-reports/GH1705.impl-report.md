# Implementation Report: GH1705

## Summary

- Eliminated the inline Darcy-Weisbach duplicate in `calc_backend/routers/pressure_drop.py` by delegating to `PressureDropCalculator` from `upstream_drift_tools.process_calculators.pressure_drop_calculator`.
- The router's own docstring admitted the duplication existed only to "avoid import issues" — those issues were resolved via correct ruff import ordering. The `R_UNIVERSAL` constants are numerically identical (8.314462618), ensuring bit-for-bit parity.
- Added `test_delegates_to_pressure_drop_calculator` as a `@pytest.mark.contract` test that verifies exact numeric parity between the router response and `PressureDropCalculator` called directly.

## Key Decisions

1. **Delegation not deletion:** The `PressureDropCalculator` class is the DRY layer. Rather than inlining physics in the router, the router now calls the shared implementation directly.
2. **No API surface change:** The `PressureDropResponse` structure is unchanged. All existing tests pass without modification.
3. **Module-level instance:** `_calculator = PressureDropCalculator()` is created at module load time (stateless class — no side effects from this pattern).
