💡 **What:**
Replaced the empty `results` array instantiation and subsequent `.push()` method calls with a pre-allocated array (`new Array<ODEResultPoint>(numPoints)`) and direct index assignments (`results[i] = point`).

🎯 **Why:**
In the high-frequency RK4 integration loop, continuously pushing objects to a dynamically growing array forces the JavaScript engine (V8) to repeatedly reallocate contiguous memory and copy elements. For numerical solvers processing hundreds or thousands of steps, this introduces unnecessary CPU overhead and garbage collection pauses. Pre-allocating the array avoids all resizing overhead.

📊 **Impact:**
Eliminates continuous memory reallocation overhead inside the `solveODESystem` hot path. Expected to moderately reduce execution time and GC pauses when calculating high-resolution or long-duration ODE solutions.

🔬 **Measurement:**
Tested locally via the `ode_solver` Vitest suite to ensure mathematical correctness was not altered (`cd src/ode_solver/web && npx vitest run`). Behavior is identical but executes slightly faster.
